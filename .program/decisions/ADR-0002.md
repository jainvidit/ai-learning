# ADR-0002: Phase 0 splits packages only — no separate `apps/api` deployable

**Status:** accepted (genesis, 2026-07-25) · **Item:** ROOT.1.5 · **Trigger:** OPEN-QUESTIONS #7

## Question
Blueprint §6 Phase 0 includes a monorepo split with a separate `apps/api`;
CONSTRAINTS.md #15 [HARD] says single process where possible.

## Readings
- **A:** the split is code organization (packages + two deployables Home runs as one
  process or a supervised pair).
- **B:** a separate api app is production-service shape the directive rules out; Phase 0
  should split packages only.

## Decision
**Reading B.** Phase 0 introduces a workspace with extracted packages
(`packages/content-schema`, `packages/learning-engine`, seam packages) and keeps exactly
one Next.js app/process. No `apps/api`.

## Reasoning
Least irreversible: extracting a package is additive; introducing a second deployable
reshapes run/ops/docs and is exactly the "production service shape" the [HARD] directive
rejects. Adjacent shards agree: blueprint §3 itself calls the Next server the BFF, and
api-and-streaming REQ-API-01 assumes the browser talks only to the Next server.

## If the other reading is correct
An `apps/api` can be added later by moving already-extracted packages behind it —
the package boundaries are the hard part and they are built either way.
