# ADR-0025: REQ-EX-01 s3 "never branches on driver" — ratification as falsifiable via grep

**Status:** Ratified  
**Date:** 2026-07-28  
**Context:** ADR-0018 enumeration schedule; unfalsifiable-criteria survey (2026-07-27T0540) classified execution-layer REQ-EX-01 s3 as borderline  
**Decider:** implementer-ROOT.7.3.7-gen0

---

## Decision

RATIFY REQ-EX-01 scenario 3 as **falsifiable as written** via a concrete grep-based check. The driver count is fixed at 2 (LocalDriver, CloudDriver; CloudDriver interface-only per ADR-0001), and both are named in the spec. The no-branching guarantee can be verified by grepping src/ for driver-type conditionals and classifying hits.

No shard edit required. The scenario text ("Given the terminal/dock UI code, when audited, then no rendering or behavior branches on which driver is active") is testable as written.

---

## Concrete falsification procedure

**Check:** Ten named grep patterns over src/ to detect all known driver-conditional mechanisms.

**CHECK 1 — instanceof checks:**
```bash
rg 'instanceof\s+(LocalDriver|CloudDriver|ExecutionDriver)' --type ts --glob 'src/**' -n
```
Catches: `driver instanceof LocalDriver`, `x instanceof CloudDriver`, `obj instanceof ExecutionDriver`

**CHECK 2 — Quoted driver literals:**
```bash
rg '(driver|driverType|driverKind)\s*[!=]==?\s*["\x27](cloud|local)["\x27]' --type ts --glob 'src/**' -n
```
Catches: `driver === "cloud"`, `driverType !== 'local'`

**CHECK 3a — .kind field access:**
```bash
rg '\b(d|driver|activeDriver|currentDriver|executionDriver)\.kind\b' --type ts --glob 'src/**' -n
```
Catches: `driver.kind`, `d.kind`, `activeDriver.kind`

**CHECK 3b — driverKind variable:**
```bash
rg '\bdriverKind\b' --type ts --glob 'src/**' -n
```
Catches: `const driverKind = ...`, `if (driverKind === ...)`

**CHECK 4 — constructor.name comparison:**
```bash
rg '(driver|execution).*\.constructor\.name' --type ts --glob 'src/**' -n
```
Catches: `driver.constructor.name === 'LocalDriver'`

**CHECK 5 — 'in' operator duck-typing:**
```bash
rg '["\x27](sandboxToken|cloudToken|localPath|cloudEndpoint)["\x27]\s+in\s+' --type ts --glob 'src/**' -n
```
Catches: `'sandboxToken' in driver`, `"cloudToken" in obj`

**CHECK 6 — config.executionMode flags:**
```bash
rg '\b(config|settings|options)\.executionMode\b' --type ts --glob 'src/**' -n
```
Catches: `config.executionMode === 'local'`, `settings.executionMode`

**CHECK 7 — process.env driver vars:**
```bash
rg 'process\.env\.(EXECUTION_DRIVER|DRIVER_TYPE|NEXT_PUBLIC_DRIVER)' --type ts --glob 'src/**' -n
```
Catches: `process.env.EXECUTION_DRIVER`, `process.env.DRIVER_TYPE`  
**Note:** `process.env.NEXT_PUBLIC_EDITION` is EXCLUDED per hosted-edition REQ-HE-01 s1 — edition deltas legitimately live in configuration; driver selection does not.

**CHECK 8 — switch on .name:**
```bash
rg 'switch.*\.name' --type ts --glob 'src/**' -n
```
Catches: `switch (activeDriver.name) { case 'local': ... }`

**CHECK 9 — Conditional dynamic import():**
```bash
rg 'import\s*\([^)]*\?[^)]*:[^)]*\)' --type ts --glob 'src/**' -n
```
Catches: `await import(driver === 'cloud' ? './cloud' : './local')`

**CHECK 10 — driver.type field:**
```bash
rg '\b(driver|execution).*\.type\b' --type ts --glob 'src/**' -n
```
Catches: `driver.type === 'local'`, `executionObj.type`

**Paths in scope:** `src/**` (all TypeScript/TSX, recursively) — the entire client and server application code outside of specs/docs.

**Allowed exceptions (composition/factory):**
**PARKED UNTIL ROOT.4.5.** The composition point does not exist today. Once ROOT.4.5 names the factory file and symbol (e.g., `src/lib/execution/factory.ts:selectDriver`), that single location may branch on driver type per the factory pattern. Until then, **NO EXCEPTIONS** — any hit in any file is a FAIL.

Exception addition procedure (per ADR-0028 exception rules):
1. ROOT.4.5 must amend this ADR with the single named file path and exported symbol
2. The justification must cite the factory pattern and confirm the symbol is the sole composition point
3. The exception is recorded in this section with the amending item ID and date

**Pass/Fail classification:**
- **PASS (current baseline):** Zero hits across all 10 checks.
- **FAIL (definitive):** Any hit in any file, until ROOT.4.5 amends this ADR with the bounded factory exception.

## Closed-world / relaxation rules

**Closed-world:** The two driver names (LocalDriver, CloudDriver) are fixed in execution-layer.md REQ-EX-01 and are unlikely to expand. If a third driver is ever added (e.g., "MockDriver" for testing), the grep pattern MUST be updated to include it.

**Relaxation:** None. The no-branching guarantee is absolute for UI/rendering code per LANE-DEPENDENCIES row (execution-layer, depended on by terminal-experience.md: "Nova's dock UX must not branch on driver"). The factory may branch to compose; nothing else may.

**Pattern updates:** If ROOT.4.5 introduces a driver-selection mechanism that does NOT use the strings "LocalDriver"/"CloudDriver" (e.g., a symbol, a numeric constant), the grep pattern must be updated to cover that mechanism. The implementer of ROOT.4.5 MUST verify the pattern still covers the shipped abstraction.

## Shard edit ruling

**No shard edit required.** REQ-EX-01 scenario 3 is falsifiable as written:  
> "Given the terminal/dock UI code, when audited, then no rendering or behavior branches on which driver is active."

The grep-based check operationalizes "when audited" as a concrete grep command, and the pass/fail rules operationalize "no rendering or behavior branches" as zero hits in UI code. The scenario does not need additional text — the falsification procedure is recorded here in the ADR per the enumeration pattern established in ADR-0017 and ADR-0028.
