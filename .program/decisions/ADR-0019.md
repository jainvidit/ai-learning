# ADR-0019: REQ-API-03 s3 SSE-endpoint domain — enumerate streaming endpoints (closed-world)

Status: ratified 2026-07-27.
Item: ROOT.7.3.1. Spec: api-and-streaming.md REQ-API-03 scenario 3.

## Context

REQ-API-03 s3 says "Given **any SSE response**, when headers are inspected, then `X-Accel-Buffering: no` and no-transform caching directives are present, and heartbeats arrive at ~20s intervals during quiet periods." The universal quantifier "any SSE response" was unfalsifiable over an unenumerated domain: no test suite can cover an open set of endpoints, so the criterion could pass review while the guarantee was false for unnamed endpoints.

The unfalsifiable-criteria survey (.program/audits/2026-07-27T0540-unfalsifiable-criteria-survey.md, row 1) identified this as a clear match — a universal phrase over an unenumerated domain (named as "playground/terminal/unspecified"). This is the same failure mode as CP-05 s1 ("content changes in any way"), which passed review while false and was fixed by enumeration in ADR-0017. Following that precedent (ADR-0017's closed-world pattern: enumerate the domain, reject outside it, relaxation is additive via new ADR), this decision enumerates the SSE-emitting endpoints bound by REQ-API-03 s3.

## The enumerated SSE-endpoint domain (normative)

REQ-API-03 s3 applies to exactly TWO SSE-emitting endpoints in the ai-learning-app:

### 1. Playground streaming endpoint — `POST /api/playground/run`
- **Route:** `src/app/api/playground/run/route.ts`
- **Owning spec:** api-and-streaming.md REQ-API-03 s1–s3; playground.md REQ-PG-01
- **Owning item:** ROOT.1.3 (API & Streaming capability, Phase 0)
- **Purpose:** Streams Claude model responses for playground exercises (text deltas + done event)
- **Protocol:** Server-Sent Events (Content-Type: text/event-stream)
- **Current state:** MODIFIED — SSE + server-side exercise loading survive; gains resumable-stream + stop endpoint per REQ-API-03 s1–s2
- **Playground resume (REQ-API-03 s1):** The resumable-stream contract (refresh reconnects with last seq without restarting the model call) is served by this same endpoint. The route will accept a `lastSeq` or similar parameter to distinguish fresh runs from resume; the SSE stream protocol and s3 obligations remain identical for both. A future implementation may factor this into a separate GET endpoint (e.g., `/api/playground/resume`), which would join this list via the relaxation path below, but the contract is specified here.

### 2. Terminal/execution streaming endpoint — `POST /api/claude-code/exec`
- **Route:** `src/app/api/claude-code/exec/route.ts`
- **Owning spec:** execution-layer.md REQ-EX-02, REQ-EX-03; api-and-streaming.md REQ-API-03
- **Owning item:** ROOT.4.5 (Execution Layer capability, Phase 2)
- **Purpose:** Streams TermEvent sequences from agent sessions (prompt-based terminal interaction: SSE-down + POST-up)
- **Protocol:** Server-Sent Events (Content-Type: text/event-stream)
- **Current state:** MODIFIED — gains ExecutionDriver + durable session log + reattach contract per execution-layer
- **Terminal reattach (REQ-EX-03 s1):** The `attach(sessionId, fromSeq)` contract for gap replay + live tail is served by this same endpoint. The route will accept a `fromSeq` parameter to distinguish initial runs from reattachment; the SSE stream protocol and s3 obligations remain identical for both. A future implementation may factor this into a separate GET endpoint (e.g., `/api/claude-code/attach`), which would join this list via the relaxation path below, but the contract is specified here.

## Closed-world rule

**The enumeration above is exhaustive.** Any endpoint not on this list is NOT bound by REQ-API-03 s3 until explicitly added by a future additive ADR. Creating an SSE-emitting endpoint not on this list without amending this ADR first is a spec violation.

The spec obligation is no longer "test one SSE endpoint and assume all others follow" (an open list) but "verify that each endpoint on the normative list satisfies the s3 obligations: X-Accel-Buffering: no, no-transform Cache-Control, and ~20s heartbeats during quiet periods."

## Per-endpoint falsifiable restatement of REQ-API-03 s3

For each endpoint in the enumerated domain:

1. **Headers:** When an SSE response is returned, then `X-Accel-Buffering: no` and `Cache-Control: no-cache, no-transform` (or equivalent no-transform directive) are present in the response headers.
2. **Heartbeats:** When the stream is idle (no model tokens or TermEvents for ~20s), then heartbeat events (e.g., `:heartbeat\n\n` comment lines or data events) are emitted at approximately 20-second intervals to prevent proxy/CDN timeouts.

These obligations are testable per endpoint: spawn a stream, read headers, wait through a quiet period, verify heartbeats arrive.

**Current header baseline (retrofit obligation for ROOT.1.3):**
- `/api/playground/run` (route.ts:113): sends `Cache-Control: no-cache` WITHOUT `no-transform` — FAILS obligation 1 today.
- `/api/claude-code/exec` (route.ts:152): sends `Cache-Control: no-cache, no-transform` — PASSES obligation 1 today.
- `X-Accel-Buffering: no` appears NOWHERE in `src/` — both endpoints FAIL this obligation today.

## Consistency check

**Execution-layer co-ownership verified:** execution-layer.md REQ-EX-02 names the durable seq-numbered event log as the architecture (not the socket type); REQ-EX-05 states the protocol is "transport-agnostic so a WS/PTY upgrade never breaks clients." api-and-streaming.md depends-on clause states "the two shards co-own the TermEvent protocol; Ramesh owns the contract." The SSE headers/heartbeats obligation (s3) applies uniformly to both endpoints; no conflict.

**Coach-and-hints excluded:** coach-and-hints.md REQ-CH-01 describes tutor invocations, which are request/response (model-gateway calls), not streaming. The survey's "any tutor invocation" universal is a separate unfalsifiable criterion (row 4, owned by ROOT.7.3.4 / ADR-0022) and does NOT emit SSE responses. No overlap.

**Judge-pipeline excluded:** judge-pipeline.md describes verdict computation, which is request/response (judge model calls return structured outputs). No SSE emission. No overlap.

**Constraints/REJECTED check:** No enumerated endpoint contradicts docs/origin/CONSTRAINTS.md or REJECTED.md. CONSTRAINTS.md #17 [HARD] states "Port 3000 is the owner's" (not touched by this ADR). REJECTED.md line 78 says "Raw PTY keystroke terminal" rejected in favor of "Prompt-based interaction" (the exec endpoint implements prompt-based, consistent). No contradiction.

**Interfaces check:** agent-runner.md lines 151-153 corroborates this ADR — headers, heartbeats, and reconnect/backoff are declared the HTTP layer's concern under REQ-API-03, not the runner's; SSE-down + POST-up is recorded as the current transport. The TermEvent protocol is co-owned by api-and-streaming + execution-layer per their frontmatter. No divergence.

## Relaxation path

To admit a new SSE-emitting endpoint:
1. Write an additive ADR that: (a) names the new endpoint (route path, owning spec/item, purpose), (b) confirms s3 obligations apply or states an exception with rationale, (c) updates this ADR's enumeration section by appending the new entry.
2. Amend api-and-streaming.md additively to reference the new ADR.
3. Implement the endpoint with s3 plumbing (headers, heartbeats) or document the exception.

Migration guidance: if an endpoint was implemented without s3 plumbing before being added to this list, its addition to the domain obligates retrofit or explicit exception.

## What was NOT enumerated and why

- **oRPC procedures (REQ-API-02):** These are request/response over HTTP POST, not streaming. oRPC JSON-Schema emission is for authoring contracts, not transport. Not SSE.
- **Model-gateway calls:** model-gateway.md describes the ModelRouter interface for LLM calls (judge, tutor, content-gen), which return structured outputs or text completions. Internally these may use streaming APIs from Bedrock, but the app-level seams (judge verdicts, tutor responses) are not exposed as SSE endpoints to the browser. Not in scope.
- **REQ-HE-02 WebSockets (hosted-edition.md):** The Hosted Edition uses WebSockets terminated by a Cloudflare Durable Object session actor, not SSE. WebSocket is a distinct transport protocol with its own connection semantics, headers, and heartbeat conventions. REQ-API-03 s3 obligations (X-Accel-Buffering, no-transform, ~20s heartbeats) are SSE/HTTP-streaming-specific and do not apply to WebSocket connections. Out of domain by protocol type. (The `attach(sessionId, fromSeq)` contract from REQ-EX-03 applies uniformly across both transports, but this ADR enumerates only SSE-emitting surfaces.)
- **beat-model "SSE-fed widgets" class (beat-model.md lines 157, 212):** The interface document names "SSE-fed widgets" as a hypothetical streaming beat class alongside terminal sessions and agent runs. No such widget surface is authored in the current corpus (as of 2026-07-27, Phase 0 near completion), and no spec requirement mandates one. If a future phase introduces an SSE-fed widget (e.g., live content-generation preview, real-time collaboration panel), it joins this list via the relaxation path above.
- **Future hypothetical endpoints:** The spec corpus (as of 2026-07-27, Phase 0 near completion) names only playground and terminal as streaming surfaces. If a future phase introduces a new streaming surface, it joins this list via the relaxation path above.

## Consequences

- api-and-streaming.md REQ-API-03 s3 amended additively to quantify over the enumerated list (domain clause added under s3).
- Acceptance tests for s3 are now endpoint-by-endpoint checks: each enumerated route must pass headers + heartbeats verification.
- Creating an SSE endpoint outside this list without an additive ADR is a spec violation (caught at review or by grep-based audit).
- The unfalsifiable "any SSE response" phrase is now bounded and testable.
