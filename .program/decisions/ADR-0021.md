# ADR-0021: REQ-MM-05 s4 struggle-signal domain — enumerate "any struggling learner" triggers

Status: ratified 2026-07-28.
Item: ROOT.7.3.3. Spec: mastery-model.md REQ-MM-05 scenario 4.

## Context

REQ-MM-05 s4 says "Given **any struggling learner**, when content is served, then the item text itself is a pre-authored/pre-validated variant — the system never rewrites content live." The universal quantifier "any struggling learner" was unfalsifiable over an unenumerated domain: no test suite can cover an open set of struggle patterns, so the criterion could pass review while the guarantee was false for unnamed patterns. This is the same defect as CP-05 s1 ("content changes in any way" — ADR-0017) and API-03 s3 ("any SSE response" — ADR-0019).

The unfalsifiable-criteria survey (.program/audits/2026-07-27T0540-unfalsifiable-criteria-survey.md, row mastery-model REQ-MM-05 s4) identified this as a clear match — a universal phrase over an unenumerated domain ("two fails, three fails… unspecified"). Following the ADR-0017 precedent (enumerate the domain, reject outside it, relaxation is additive), this decision enumerates the struggle triggers that fire adaptive difficulty in the ai-learning-app.

## The enumerated struggle-trigger domain (normative)

REQ-MM-05 s4 quantifies over exactly FOUR struggle-signal patterns that trigger adaptive responses:

### Trigger 1: Two consecutive clear-misses on the same skill
- **Detection rule:** 2 consecutive attempts on exercises tagged with the same `skillId`, both grading clear-miss (normalized score <0.4, per mastery-model REQ-MM-03), without an intervening clear-pass (score >0.7) on that skill.
- **Adaptive response:** The next item selected for that skill steps down one tier (stretch→core, core→intro) AND a prerequisite probe is injected before it (REQ-MM-05 s1).
- **Testable behavior:** Given `skill-A` attempts [clear-miss, clear-miss], when the next item is selected, then it is one tier lower than the previous AND a prerequisite probe precedes it in the queue.
- **Sourcing:** mastery-model.md REQ-MM-05 s1 ("two fails step down a tier and inject a prerequisite probe").

### Trigger 2: Three failures on a skill → struggle-halt
- **Detection rule:** 3 failed attempts (clear-miss OR in-band score 0.4–0.7) on the same `skillId` within the same session OR across sessions if no intervening pass exists.
- **Adaptive response:** Difficulty escalation STOPS (no further tier-stepping). The coach affordance is visually surfaced (highlighted) at the reflective rung (coach-and-hints REQ-CH-02: "struggle-watcher surfaces, never auto-opens"). The learner can continue without using the coach — this is a surfacing, not a gate.
- **Testable behavior:** Given `skill-B` attempts [fail, fail, fail], when the third lands, then the coach button is visually highlighted AND no further automatic tier-stepping occurs for that skill until the coach is used or a pass is achieved.
- **Sourcing:** mastery-model.md REQ-MM-05 s2 ("three fails trigger struggle-halt into the tutor ladder at the reflective rung"); coach-and-hints REQ-CH-02 ("struggle-watcher surfaces … never auto-opens"); GLOSSARY.md "Struggle-halt".

### Trigger 3: Attempted-only completion (zero mastery evidence signal)
- **Detection rule:** A playground or exploratory beat is marked complete via `attempted` predicate without achieving a passing state (lesson-experience REQ-LX-02: "playground and exploratory beats only `attempted`").
- **Adaptive response:** Completion credit is granted (lesson advances), but ZERO mastery evidence is recorded (Sage's firewall). The skill stays in review rotation at its current state; the scheduler continues serving items for that skill at the learner's existing tier.
- **Testable behavior:** Given a playground beat completed via `attempted` (not passing), when mastery evidence is checked, then zero evidence events exist for that beat AND the lesson is marked complete AND the associated skill's mastery state is unchanged.
- **Sourcing:** lesson-experience.md REQ-LX-02 s2 ("attempted-only completions emit zero mastery evidence — Sage's firewall").
- **Note:** This is a struggle signal by construction — the learner engaged but did not pass — but the adaptive response is evidence-suppression, not content-switching or coach-surfacing. It guards mastery honesty for exploratory/open-ended exercises.

### Trigger 4: Rung-4-assisted pass → redemption probe
- **Detection rule:** A pass (clear-pass or passing normalized score) is achieved immediately following rung-4 coach guidance (coach-and-hints REQ-CH-03, REQ-CH-04).
- **Adaptive response:** Completion credit is granted, but mastery evidence is reduced or zero. The skill remains in review rotation and a later indistinguishable **redemption probe** (an isomorphic warm-up item) is scheduled to restore full evidence credit if passed without guidance (coach-and-hints REQ-CH-04: "redemption probe").
- **Testable behavior:** Given a pass after rung-4 guidance, when evidence is recorded, then completion is credited AND mastery evidence is zero or reduced AND a redemption probe appears later in the review queue AND when that probe passes, full mastery credit flows normally.
- **Sourcing:** coach-and-hints REQ-CH-04 ("rung-4-assisted passes emit reduced/zero mastery evidence; redemption probe"); GLOSSARY.md "Redemption probe".
- **Note:** The trigger is "pass after maximal help," which is a struggle marker; the response is deferred full-credit, maintaining mastery honesty.

## Closed-world rule

**The enumeration above is exhaustive.** Any struggle pattern not on this list receives the default adaptive behavior: standard item selection continues per the learner's current state + retrievability (FSRS), no tier-stepping, no coach-surfacing, evidence recorded per normal firewall rules (mastery-model REQ-MM-03). Creating a new struggle-triggered adaptive behavior without amending this ADR first is a spec violation.

Patterns explicitly NOT enumerated (and thus defaulting to standard behavior):
- **Single isolated failures:** One clear-miss does not trigger tier-stepping or coach-surfacing. Evidence is recorded per the firewall (clear-miss = Again grade, contributes to FSRS stability reset invisibly per REQ-MM-02 s5, but does not change mastery state).
- **Cross-skill failure bursts:** Multiple failures across different skills in one session. Each skill is counted independently; no cross-skill aggregate triggers adaptivity.
- **Long-idle returns with probe misses:** Gentle decay path (Fluent→Practiced via "worth a refresh" after 45+ days idle plus missed probe, per REQ-MM-02 s6). This affects state display but does not trigger tier-stepping or coach-surfacing — it's a decay surface, not a struggle signal.
- **In-band scores (0.4–0.7) without consecutive pattern:** An isolated in-band score (judge-noise firewall, REQ-MM-03: "0.4–0.7 emits a scheduler grade but ZERO mastery evidence") does not alone trigger tier-stepping. It counts toward the "three failures" threshold (Trigger 2) if part of a consecutive pattern.
- **Low-confidence clear-passes:** A clear-pass with low ensemble confidence (evidence quote verification failed, low vote agreement — judge-pipeline REQ-JP-03) may have shrunk evidence but does not trigger adaptivity beyond normal evidence accounting.
- **Response timing:** EXPLICITLY REJECTED (consistency check below). Any timing-based threshold (e.g., "solve in <30s = Easy, >5min = struggle") is a violation of REJECTED.md line 42 ("Timing-based grading violates non-competitive constraint").

## Consistency checks

### REJECTED.md verification (acceptance criterion 3, HARD CHECK)

1. **EMA learner-facing mastery (REJECTED.md line 43):** "Any learner-facing continuous number invites false precision and leaks judge noise; discrete evidence-counted states won." — VERIFIED: No enumerated trigger produces or displays a continuous mastery percentage. All triggers operate on discrete states (Introduced/Practiced/Fluent) and count-based thresholds (2 consecutive, 3 failures). Mastery-model REQ-MM-02 s7 already forbids learner-facing continuous numbers; this ADR introduces no contradiction.

2. **Timing-based grading (REJECTED.md line 42):** "Timed pressure by the back door — violates non-competitive constraint" (original proposal was "fast clean answer = Easy"). — VERIFIED: No enumerated trigger keys on response timing, dwell time, or speed. Triggers 1 and 2 count attempts (clear-miss vs clear-pass, normalized score thresholds); Triggers 3 and 4 key on completion predicates and coach usage, not time. The "dwell ≫ estimate" phrase in coach-and-hints REQ-CH-02 ("struggle-watcher: attempts > N, repeated same-criterion misses, dwell ≫ estimate") is cited but NOT enumerated as a distinct trigger here because REQ-CH-02 only surfaces the coach affordance visually (highlights the button) — it does not change content selection or evidence accounting. If a future phase proposes dwell-based adaptivity (e.g., "dwell >10min on a beat with no attempt → inject a hint"), that would require an additive ADR and explicit REJECTED.md reconciliation (timing as a non-competitive affordance-surfacing signal vs. timing as grading input).

### Adjacent-shard consistency

1. **mastery-model REQ-MM-02 (never-demote invariant):** s5 says "any number of subsequent failures" → skill remains Fluent. — CONSISTENT: Triggers 1 and 2 (consecutive/three fails) do NOT demote states. They adjust tier selection and surface the coach, but the skill's mastery state (Introduced/Practiced/Fluent) is unchanged. The only demotion path remains gentle decay (Fluent→Practiced via 45+ idle days + missed probe, s6), which is pattern-listed but not a Trigger-1/2 adaptivity response.

2. **mastery-model REQ-MM-03 (judge-noise firewall):** In-band scores (0.4–0.7) emit scheduler grade, zero evidence. — CONSISTENT: Trigger 2 counts in-band scores as "failures" for the three-fails threshold (struggle-halt is about learner experience, not evidence honesty), but in-band attempts contribute zero evidence per REQ-MM-03. No contradiction.

3. **judge-pipeline REQ-JP-04 (ADR-0020 failure-pattern domain):** Enumerates six failure patterns for the never-demote invariant. — COEXISTS: ADR-0020's patterns govern state-preservation behavior ("Fluent skill + failures → still Fluent"); this ADR's triggers govern adaptive responses (tier-stepping, coach-surfacing, evidence-suppression). No overlap in obligations. Cross-reference noted.

4. **coach-and-hints REQ-CH-02 (on-demand affordance):** "Struggle-watcher surfaces, never auto-opens." — CONSISTENT: Trigger 2 explicitly states the coach button is "visually highlighted" (surfaced), not auto-opened. The learner chooses whether to engage.

5. **lesson-experience REQ-LX-02 (attempted-only firewall):** "Attempted-only completions emit zero mastery evidence." — IDENTICAL: Trigger 3 restates this verbatim as a struggle signal with adaptive response (evidence-suppression). No conflict.

## Relaxation path

To admit a new struggle-triggered adaptive behavior:
1. Write an additive ADR that: (a) names the new trigger with its detection rule, (b) specifies the adaptive response and testable behavior, (c) cites sourcing in spec shards or new requirements, (d) runs consistency checks against REJECTED.md (especially timing-based grading and EMA mastery) and adjacent shards, (e) updates this ADR's enumeration section by appending the new entry.
2. Amend mastery-model.md additively to reference the new ADR and trigger.
3. Implement the trigger with its detection and response logic.

Migration guidance: if a struggle pattern was observed in production that does not map to an enumerated trigger, its addition to the domain obligates explicit design and falsifiable testing (no silent default-behavior creep).

## What was NOT enumerated and why

- **"Dwell ≫ estimate" from coach-and-hints REQ-CH-02:** The requirement text says "struggle-watcher (attempts > N, repeated same-criterion misses, dwell ≫ estimate)" surfaces the coach affordance. "Repeated same-criterion misses" is covered by Trigger 2 (three fails). "Dwell ≫ estimate" is NOT enumerated as a distinct trigger because REQ-CH-02's only obligation is visual surfacing (highlight the button), not adaptive selection or evidence change. If dwell-based adaptivity is desired in future (e.g., auto-inject a hint after 10min dwell), that would be a new trigger via the relaxation path, requiring REJECTED.md consistency check (timing-based grading is rejected, but timing as an affordance signal may be allowable — that distinction needs explicit ruling).

- **"Ungradeable-content path" (judge-pipeline REQ-JP-04):** Manipulation attempts (injection pre-screen) route to quarantine with zero evidence and no completion event. This is NOT a struggle signal — it's a data-integrity response. The learner is not struggling with the content; they are experimenting with the system. Not in domain.

- **Boss-flagged exercises (lesson-experience REQ-LX-02 s3):** "Boss-flagged exercises are excluded entirely: a boss counts toward nothing until passed." — NOT a struggle trigger. Bosses gate Mastered state (mastery-model REQ-MM-04), but failing a boss does not trigger tier-stepping or coach-surfacing beyond normal per-skill adaptivity (if the boss tests `skill-X`, then failing it counts as a `skill-X` failure per Triggers 1/2).

- **Skill with all-judge evidence (REQ-MM-02 s3):** "Practiced skill with 3 clear positives all from judge verdicts (zero deterministic), when promotion is evaluated, then it does NOT become Fluent." — NOT a struggle signal. This is an evidence-quality gate (Fluent requires ≥1 deterministic success), not a learner-struggle response.

## Consequences

- mastery-model.md REQ-MM-05 s4 amended additively to quantify over the enumerated triggers (domain clause replaces "any struggling learner" with "any learner matching enumerated struggle triggers 1–4").
- Acceptance tests for adaptivity are now per-trigger checks: each enumerated trigger must have a test that detects the pattern and verifies the adaptive response.
- Implementing a new struggle-triggered behavior without an additive ADR is a spec violation (caught at review or by grep-based audit).
- The unfalsifiable "any struggling learner" phrase is now bounded and testable.
