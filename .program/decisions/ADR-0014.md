# ADR-0014 — The reviewer/auditor read-only guarantee: never enforced, now narrowed

**Status:** accepted (2026-07-26) · **Companion to:** ADR-0013 (`memory:` ban) ·
**Enforcement:** deferred to Phase 5 permission deny rules ·
**Inputs:** 125 subagent transcripts under
`.claude/projects/C--Users-jainv-workplace-ai-learning-app/*/subagents/agent-*.jsonl`,
role files in `.program/roles/`

## Context

Five roles — `dream-reviewer-primary`, `-secondary`, `-adversarial`,
`dream-ledger-auditor`, `-deep` — describe themselves as READ-ONLY, in the frontmatter
`description:` and again in a "Hard stops: read-only — you have no Write, Edit or Agent
tool and must not attempt to obtain one" line in the body.

Two separate things were wrong with that claim.

1. Write and Edit **were** present, silently granted by `memory: project` (ADR-0013).
   That is fixed.
2. Even with Write and Edit gone, **the guarantee still does not hold**, because all five
   roles have Bash. `npm test > somefile.txt`, `mkdir -p`, `mv`, `rm`, `tee`, a heredoc
   into any path — Bash writes anywhere the OS user can write. A tools allowlist that
   omits Write and Edit while including Bash does not produce a read-only agent, and never
   did.

## Decision

**The read-only guarantee was never enforced by the tools list, and a tools list cannot
enforce it. It is narrowed to a path constraint and moved to the permission layer.**

### Reviewers keep Bash. Deliberately.

This is not an oversight left in place for convenience. PART 6 of the operating prompt
requires empirical verification: a reviewer that cannot run `npm test`, `npx tsc
--noEmit`, or `npm run lint` cannot independently confirm anything and is reduced to
reading the implementer's own claims about its own work — exactly the failure mode blind
review exists to prevent. Framework-API claims in particular are only settleable by
running code, because this Next.js version diverges from training data (AGENTS.md). The
reviewers' value comes from re-running the evidence themselves. Removing Bash would buy a
guarantee nobody needs at the cost of the only thing that makes a review credible.

### The narrowed guarantee

> **Reviewers and auditors may write only under `.program/audits/**`.**

Everything else is out of bounds: artifacts under review, ledger item files, ledger event
files, `src/**`, `tests/**`, `content/**`, git, and role files.

Rationale for allowing that one path: reviewers legitimately need somewhere to put
verification output. The single Bash-write pattern observed in 38 generations was exactly
this — `dream-reviewer-primary` on ROOT.1.1.3 captured four command outputs to
`.program/audits/ROOT.1.1.3-verification/reviewer-*.txt`, namespaced under a `reviewer-`
prefix that cannot collide with the implementer's own evidence files, and not cited by any
`verification:` block as if it were the implementer's. That is a reviewer strengthening
its own verdict with independently produced evidence. It is the behaviour we want, so the
rule permits it rather than forcing reviewers to discard their evidence or launder it
through their return value.

### Enforcement, and where it is NOT

- **Enforced by:** deny rules in `.claude/settings.json` (Phase 5) — Bash write patterns
  and Write/Edit targets outside `.program/audits/**`.
- **Never enforced by:** the `tools:` declaration in a role file. Recording this
  explicitly because the previous design believed it was, and that belief is what let a
  structurally-absent guarantee go unnoticed across 38 generations.
- Prose in a role file remains useful as instruction — agents did in fact respect it — but
  it is a request, not a boundary. The distinction matters when writing future guarantees:
  if a claim of the form "this agent cannot X" appears anywhere, there must be a deny rule
  behind it or the claim is false.

### Was it exercised?

No. Established by sweeping all 125 subagent transcripts with per-record
`attributionAgent` (necessary because the relauncher's `git add -A` destroyed git
attribution — ADR-0012). Across every dispatch of the five roles: zero writes to any
artifact under review, any ledger item, or any source file; zero memory writes (all three
`.claude/agent-memory/` directories were empty, 0 files, now deleted); one scratch probe
written and self-deleted 7 seconds later outside the artifact; the four
`.program/audits/**` captures described above; and one `mv .next .next.backup` **denied**
by the permission system. Review independence is intact and all 13 `done` items keep their
verdicts — a `review_guarantee_breach_unexercised` event records this on each.

## Consequence

Corrections applied to the record, so no document claims a guarantee that does not exist:

- All five role files: the `description:` line and the "Hard stops" line now state the
  narrowed rule and name Bash as the reason, instead of asserting read-only.
- The claim "you have no Write, Edit or Agent tool" is replaced by "do not write outside
  `.program/audits/**`" — a rule an agent can actually comply with, and one that stays
  true if the tool set changes again.
- `dream-reader-lookup` keeps its stronger claim: it has no Bash, so it is genuinely
  read-only. `dream-reader-corpus`, `dream-verifier`, `dream-verifier-deep` have Bash and
  are corrected the same way as the five.
- Until the Phase 5 deny rules land, the narrowed guarantee is prose-only and therefore
  unenforced. That gap is open and known, not resolved by this ADR.

## Appendix — the ToolSearch discrepancy, resolved

Phase 2 produced two apparently contradictory readings: the role files declare
`tools: Read, Grep, Glob, Bash, ToolSearch` for the three reviewers, but the runtime tool
list showed only `Read, Grep, Glob, Bash`.

**Both were accurate reports of different things, and the runtime one is the operative
truth.** Re-probed on 2026-07-26 by dispatching all three reviewers with a diagnostic
prompt asking them to enumerate their own tools without using any. All three returned,
independently and identically:

```
Read, Grep, Glob, Bash
ToolSearch: ABSENT
```

So: **ToolSearch is declared in the frontmatter and not granted at runtime.** Nothing was
changed to make the two agree — the declaration is left in place deliberately, because the
discrepancy is itself a finding: a name in a `tools:` list is a request, and the runtime
grant is the fact. This is the same lesson as the body of this ADR from the opposite
direction — `memory:` added tools that were not declared, and `ToolSearch` was declared but
not added. **The frontmatter `tools:` list is neither a floor nor a ceiling. Never reason
about an agent's capabilities from it; enumerate at runtime.**

Practical consequence: the three reviewers cannot reach deferred/MCP tools. Nothing in the
38 generations depended on that — every reviewer check ran through Bash — so no verdict is
affected. If a reviewer is ever given work that needs ToolSearch, verify the grant with a
probe first rather than trusting the declaration.

## If wrong

If a reviewer is ever found to have written outside `.program/audits/**`, the deny rules
are incomplete — check Bash redirection and heredoc forms first, since those are what a
Write/Edit-shaped deny rule misses. If a reviewer's verdict is ever suspected of
contamination, the transcripts are the evidence of record, not git: per-record
`attributionAgent` gives exact per-agent attribution and survives the loop's sweeping
commits.
