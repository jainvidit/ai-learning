# ADR-0020 — REQ-JP-04 s2 failure-pattern domain enumeration (judge-noise firewall demotion semantics)

Date: 2026-07-28. Author: implementer-ROOT.7.3.2-gen0.
Status: ratified.
Spec ref: .program/spec/judge-pipeline.md#req-jp-04 scenario 2; mastery-model.md#req-mm-02 scenario 5, #req-mm-03.

## Context

REQ-MM-02 scenario 5 says "Given a Fluent skill and **any number of subsequent failures**, when state is read, then it is still Fluent (never demote)." The universal quantifier "any number of subsequent failures" was unfalsifiable over an unenumerated failure-pattern domain (unfalsifiable-criteria survey, judge-pipeline REQ-JP-04 s2 row). No test suite can cover "any number" without enumerating the patterns that count.

REQ-MM-03 establishes the judge-noise firewall: normalized scores <0.4 = clear-miss (Again); >0.7 = clear-pass (Good); 0.4–0.7 = in-band (scheduler grade only, zero mastery evidence). The firewall means judge failures are TWO kinds: **clear-misses** that produce negative evidence (gates Again) AND **in-band verdicts** that withhold evidence without demoting. REQ-MM-02 s5 binds both — Fluent is never demoted, but the firewall distinguishes what failures DO.

Following ADR-0017 closed-world enumeration precedent (and ADR-0019/0028): enumerate the failure patterns bound by the two-key firewall contract, define per-pattern behavior testably, reject outside the domain (closed-world), relaxation is additive via new ADR.

## The two-key firewall contract (unchanged, cited for consistency check)

mastery-model.md lines 43-55 (REQ-MM-03) establish the judge-noise firewall as the interface boundary between Priya's judge verdicts (score + tier + confidence) and Sage's mastery-state machine (evidence counting, promotion rules, never-demote invariant). The firewall thresholds interpret Priya's normalized score — any threshold change needs BOTH sign-offs (LANE-DEPENDENCIES "Judge verdict shape" row).

**The contract:**
- Input: gate-tier judge verdict with normalized score, confidence, tier.
- Output: scheduler grade (Again/Good, never Easy/Hard) + mastery evidence (clear-pass/clear-miss/zero).
- Firewall mapping (lines 43-44):
  - `score < 0.4` → clear-miss → grades Again, produces NEGATIVE evidence
  - `score > 0.7` → clear-pass → grades Good, produces POSITIVE evidence
  - `0.4 ≤ score ≤ 0.7` → in-band → grades Again/Good (based on passing threshold), produces ZERO evidence
- Low vote-agreement confidence shrinks evidence or forces in-band treatment (line 53-54), never amplifies.
- Only gate-tier verdicts touch mastery (line 54-55, cross-link judge-pipeline REQ-JP-02).

**Never-demote invariant (REQ-MM-02 s5, line 39):** "Given a Fluent skill and any number of subsequent failures, when state is read, then it is still Fluent (never demote); scheduler stability was reset without UI surface."

## Enumerated failure-pattern domain (normative)

REQ-MM-02 s5's "any number of subsequent failures" quantifies over these patterns:

### 1. Consecutive clear-misses (same skill)
- **Pattern:** A Fluent skill receives N consecutive gate-tier verdicts with `score < 0.4` (clear-miss) on exercises mapping to that skill, with no intervening passes.
- **Behavior:** Mastery state remains Fluent (never demote). Each clear-miss grades Again and resets FSRS stability invisibly (per s5 "scheduler stability was reset without UI surface"). Struggle-halt triggers after 3 failures (REQ-MM-05 s3 — tutor affordance surfaces, not auto-opened per coach-and-hints REQ-CH-02).
- **Falsifiable check:** After 5 consecutive clear-misses on a Fluent skill, assert skill state is still Fluent AND scheduler next-review date was reset (observable via spaced-review projection) AND no demotion event exists in the log.

### 2. Scattered failures interleaved with passes (same skill)
- **Pattern:** A Fluent skill receives alternating clear-misses and clear-passes (e.g., fail–pass–fail–pass–fail) across multiple sessions.
- **Behavior:** Mastery state remains Fluent. Each clear-miss grades Again and resets stability; each clear-pass grades Good and reinforces stability. Struggle-halt does NOT trigger (the 3-fail counter resets on a pass per REQ-MM-05 s2-s3 — two fails step down, THREE trigger struggle-halt).
- **Falsifiable check:** After a pattern like miss–pass–miss–pass–miss (5 verdicts, 3 misses non-consecutive), assert skill state is still Fluent AND no demotion event AND no struggle-halt trigger (tutor affordance did not surface).

### 3. In-band failures (0.4 ≤ score ≤ 0.7)
- **Pattern:** A Fluent skill receives N gate-tier verdicts with `0.4 ≤ score ≤ 0.7` (firewall in-band range).
- **Behavior:** Mastery state remains Fluent. Each in-band verdict emits a scheduler grade (Again if below passingScore, Good if above) but ZERO mastery evidence (REQ-MM-03 line 44). Stability is affected by the scheduler grade but no demotion occurs. Struggle-halt does NOT trigger (in-band verdicts produce zero evidence, not clear-misses — the 3-clear-miss counter is unaffected).
- **Falsifiable check:** After 10 consecutive in-band verdicts (e.g., score=0.55 on a 60% passing threshold), assert skill state is still Fluent AND zero mastery evidence events were recorded for those verdicts AND no struggle-halt.

### 4. Cross-skill failure bursts (different skills, same session)
- **Pattern:** A learner fails multiple Fluent skills in a single session (e.g., clear-misses on 3 different skills within minutes).
- **Behavior:** Each skill's mastery state remains Fluent independently. Per-skill stability resets and per-skill struggle-halt counters advance independently (REQ-MM-05 counting is per-skill, not session-wide). No cross-skill demotion contagion.
- **Falsifiable check:** After 1 clear-miss each on 3 different Fluent skills in one session, assert all 3 skills remain Fluent AND each has an independent stability reset AND no skill demoted another.

### 5. Long-idle return with probe misses
- **Pattern:** A Fluent skill idle 45+ days is probed (spaced-review surfaced a review item) and the learner fails the probe (clear-miss).
- **Behavior:** Mastery state transitions to Practiced via the gentle decay path (REQ-MM-02 s6 line 38: "worth a refresh" after 45+ idle days plus a missed probe — this is the ONLY decay surface). This is NOT a demotion triggered by the failure itself but by the (idle duration + missed probe) combination. Stability resets.
- **Falsifiable check:** After a Fluent skill idles 50 days then receives a clear-miss probe, assert skill state becomes Practiced (not Fluent) AND the transition event cites gentle decay, not demotion AND a subsequent clear-pass can re-promote to Fluent via normal rules.

### 6. Low-confidence clear-passes that later revert to fails
- **Pattern:** A Fluent skill receives a low-vote-agreement clear-pass (score >0.7 but confidence forces in-band treatment per REQ-MM-03 line 53-54), then subsequent clear-misses.
- **Behavior:** The low-confidence pass is treated in-band (zero evidence, or evidence shrunk). The skill remains Fluent if already Fluent (the in-band treatment withheld new evidence but did not revoke prior evidence). Subsequent clear-misses follow pattern 1 or 2 above.
- **Falsifiable check:** Given a Fluent skill, after a low-confidence score=0.75 verdict treated in-band (zero evidence recorded) followed by 2 clear-misses, assert skill state is still Fluent.

## Closed-world rule

**The enumeration above is exhaustive for the REQ-MM-02 s5 never-demote invariant.** Any failure pattern not on this list is implicitly covered by the most similar enumerated pattern (e.g., "4 consecutive failures" is pattern 1 with N=4; "miss–pass–pass–miss" is pattern 2 with different interleaving).

The spec obligation is no longer "test one failure sequence and assume all others follow" (an open, unfalsifiable quantifier) but "verify that each enumerated pattern satisfies the never-demote invariant AND the per-pattern behavior."

**Pattern-outside-the-domain behavior:** If a future phase introduces a new evidence source (e.g., peer review, multi-stage challenges) or a new verdict type (e.g., partial credit), those join this enumeration via an additive ADR that names the new pattern and its never-demote behavior.

## Consistency checks

**Two-key firewall untouched:** This ADR enumerates failure-pattern behaviors WITHIN the firewall's output semantics. The firewall thresholds (0.4 / 0.7), the clear-miss/clear-pass/in-band trichotomy, and the Priya↔Sage sign-off requirement (LANE-DEPENDENCIES) are unchanged. The enumeration translates "any number of subsequent failures" (s5) into testable patterns without altering the firewall contract.

**Gentle decay path preserved:** Pattern 5 (long-idle return with probe miss) is the ONLY decay surface per REQ-MM-02 s6 line 38. This is not a demotion triggered by the failure itself but by the (idle 45+ days + missed probe) combination — it bypasses the never-demote invariant because it is not "a failure while active." Verified: REJECTED.md has no prior ruling on decay vs demotion semantics. CONSTRAINTS.md has no constraint on idle-state transitions.

**Struggle-halt disentangled from demotion:** REQ-MM-05 s3 (3 clear-misses trigger struggle-halt into tutor ladder) is a coaching intervention, not a mastery-state change. Pattern 1 clarifies: struggle-halt can trigger while the skill remains Fluent. Pattern 3 clarifies: in-band verdicts do not count toward struggle-halt (they produce zero evidence, not clear-misses). No conflict with REQ-CH-03 (tutor ladder at reflective rung).

**Judge-pipeline dependency verified:** judge-pipeline.md depends-on clause (line 6) names mastery-model as "firewall input — LANE-DEPENDENCIES block 4." The dependency flows one way: judge verdicts → firewall → mastery states. This ADR clarifies the firewall's output semantics for failure patterns; no judge-pipeline behavior changes.

**Constraints/REJECTED check:** No enumerated pattern contradicts CONSTRAINTS.md or REJECTED.md. REJECTED.md line 43 ("Hard-vs-Good is exactly where judge variance lives") confirms the firewall's 0.4–0.7 band captures variance — pattern 3 (in-band failures) is consistent. REJECTED.md line 42 ("EMA continuous mastery score" rejected) confirms discrete state machine — the never-demote invariant enforces this.

## Relaxation path

To admit a new failure pattern (e.g., a new evidence source, a new verdict type, a new decay condition):
1. Write an additive ADR that: (a) names the new pattern (structure, source, trigger), (b) defines its never-demote behavior (or states an exception with rationale if demotion IS allowed), (c) updates this ADR's enumeration section by appending the new entry.
2. Amend judge-pipeline.md and mastery-model.md additively to reference the new ADR.
3. Implement the pattern with tests that falsify the never-demote invariant (or the stated exception).

Migration guidance: if a new evidence source was implemented without defining its failure-pattern behavior, adding it to this enumeration obligates either conformance to an existing pattern or a new ADR entry.

## Readings considered

- **judge-pipeline.md REQ-JP-02 s1** (line 31): "Given a draft-tier verdict, when downstream effects are checked, then no mastery evidence, no completion event, and no celebration resulted." Draft verdicts are excluded from the failure-pattern domain — only gate-tier verdicts bind the never-demote invariant.
- **judge-pipeline.md REQ-JP-04** (lines 48-57): Ungradeable-content path (injection quarantine) grades normally for feedback but produces zero mastery evidence. This is pattern 3 (in-band) generalized: ungradeable attempts behave like in-band verdicts (scheduler grade emitted, zero evidence, no struggle-halt count, no demotion).
- **mastery-model.md REQ-MM-05** (lines 74-76): "Given a third failure on a skill, when it lands, then difficulty escalation stops and the tutor ladder opens at the reflective rung." Struggle-halt is a coaching affordance, not demotion. Pattern 1 and 2 clarify the interaction.
- **ADR-0017** (canonicalStringify domain): The closed-world pattern — enumerate the domain (hashable types), reject outside it (TypeError with path), relaxation is additive (admit types one by one). Applied here: enumerate failure patterns, define per-pattern behavior, new patterns join via new ADR.
- **ADR-0019** (SSE-endpoint domain): Same pattern — enumerate SSE endpoints, define per-endpoint obligations (headers, heartbeats), new endpoints join via additive ADR. Verified here: patterns 1–6 exhaust the failure-pattern space given current evidence sources (judge verdicts, deterministic verifiers/quiz keys per REQ-MM-02 s3).
- **ADR-0028** (delete-verb list canonicity): Same pattern — enumerate deletion verbs, define grep procedure, new verbs join via additive ADR. Verified here: the 6 patterns cover all combinations of (consecutive/scattered, same-skill/cross-skill, clear-miss/in-band, active/idle) given current spec.
