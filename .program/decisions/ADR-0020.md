# ADR-0020 — REQ-JP-04 s2 failure-pattern domain enumeration (judge-noise firewall demotion semantics)

Date: 2026-07-28 (gen0), amended 2026-07-28 (gen1). Author: implementer-ROOT.7.3.2-gen0 (gen0), implementer-ROOT.7.3.2-gen1 (gen1).
Status: ratified.
Spec ref: .program/spec/judge-pipeline.md#req-jp-04 scenario 2; mastery-model.md#req-mm-02 scenario 5, #req-mm-03.

## Context

REQ-MM-02 scenario 5 says "Given a Fluent skill and **any number of subsequent failures**, when state is read, then it is still Fluent (never demote)." The universal quantifier "any number of subsequent failures" was unfalsifiable over an unenumerated failure-pattern domain (unfalsifiable-criteria survey, judge-pipeline REQ-JP-04 s2 row). No test suite can cover "any number" without enumerating the patterns that count.

REQ-MM-03 establishes the judge-noise firewall: normalized scores <0.4 = clear-miss (Again); >0.7 = clear-pass (Good); 0.4–0.7 = in-band (scheduler grade only, zero mastery evidence). The firewall means judge failures are TWO kinds: **clear-misses** that produce negative evidence (gates Again) AND **in-band verdicts** that withhold evidence without demoting. REQ-MM-02 s5 binds both — Fluent is never demoted, but the firewall distinguishes what failures DO.

Following ADR-0017 closed-world enumeration precedent (and ADR-0019/0028): enumerate the failure patterns bound by the two-key firewall contract, define per-pattern behavior testably, reject outside the domain (closed-world), relaxation is additive via new ADR.

## The two-key firewall contract (unchanged, cited for consistency check)

mastery-model.md lines 43-55 (REQ-MM-03) establish the judge-noise firewall as the interface boundary between Priya's judge verdicts (score + tier + confidence) and Sage's mastery-state machine (evidence counting, promotion rules, never-demote invariant). The firewall thresholds interpret Priya's normalized score — any threshold change needs BOTH sign-offs (LANE-DEPENDENCIES "Judge verdict shape" row).

**The contract:**
- Input: gate-tier judge verdict with normalized score, confidence, tier.
- Output: scheduler grade (Again/Good, never Easy/Hard) + mastery evidence (clear-pass/clear-miss/zero).
- Firewall mapping (lines 43-44):
  - `score < 0.4` → clear-miss → grades Again, produces NEGATIVE evidence
  - `score > 0.7` → clear-pass → grades Good, produces POSITIVE evidence
  - `0.4 ≤ score ≤ 0.7` → in-band → grades Again/Good (based on passing threshold), produces ZERO evidence
- Low vote-agreement confidence shrinks evidence or forces in-band treatment (line 53-54), never amplifies.
- Only gate-tier verdicts touch mastery (line 54-55, cross-link judge-pipeline REQ-JP-02).

**Never-demote invariant (REQ-MM-02 s5, line 39):** "Given a Fluent skill and any number of subsequent failures, when state is read, then it is still Fluent (never demote); scheduler stability was reset without UI surface."

## Enumerated failure-pattern domain (normative)

REQ-MM-02 s5's "any number of subsequent failures" quantifies over these patterns:

### 0. Deterministic failures (added gen1, F1)
- **Pattern:** A Fluent skill receives deterministic verifier or quiz-key failures (no normalized score; these are pass/fail binary checks).
- **Behavior:** Mastery state remains Fluent (never demote). Deterministic failures are scoreless, so the firewall trichotomy does not apply; they grade Again per spaced-review REQ-SR-02 line 26 and reset scheduler stability invisibly (same as clear-miss scheduler effects, per mastery-model REQ-MM-02 s5 "scheduler stability was reset without UI surface"). Struggle-halt counting deferred to ADR-0021 (mastery-model REQ-MM-05 Trigger 2 owns the counter).
- **Falsifiable check:** After 5 consecutive deterministic failures on a Fluent skill, assert skill state is still Fluent AND scheduler next-review date was reset (observable via spaced-review projection).

### 1. Consecutive clear-misses (same skill)
- **Pattern:** A Fluent skill receives N consecutive gate-tier verdicts with `score < 0.4` (clear-miss) on exercises mapping to that skill, with no intervening passes.
- **Behavior:** Mastery state remains Fluent (never demote). Each clear-miss grades Again and resets FSRS stability invisibly (per s5 "scheduler stability was reset without UI surface"). Struggle-halt counting deferred to ADR-0021 (mastery-model REQ-MM-05 s2 line 76 Trigger 2: "Given a third failure on a skill, when it lands, then difficulty escalation stops and the tutor ladder opens at the reflective rung" — tutor affordance surfaces, not auto-opened per coach-and-hints REQ-CH-02). **Amnesty-window exception (gen1, F2):** The FIRST clear-miss after a 21+-day idle gap emits ZERO negative mastery evidence (spaced-review REQ-SR-01 s4 line 22); scheduler still updates; subsequent failures follow normal behavior.
- **Falsifiable check:** After 5 consecutive clear-misses on a Fluent skill, assert skill state is still Fluent AND scheduler next-review date was reset (observable via spaced-review projection).

### 2. Scattered failures interleaved with passes (same skill)
- **Pattern:** A Fluent skill receives alternating clear-misses and clear-passes (e.g., fail–pass–fail–pass–fail) across multiple sessions.
- **Behavior:** Mastery state remains Fluent. Each clear-miss grades Again and resets stability; each clear-pass grades Good and reinforces stability. Struggle-halt does NOT trigger because failures are not CONSECUTIVE (ADR-0021 Trigger 1: two consecutive clear-misses step down a tier; Trigger 2: three failures on a skill open tutor ladder — consecutiveness/reset semantics owned by ADR-0021). **Amnesty-window exception (gen1, F2):** The FIRST clear-miss after a 21+-day idle gap emits ZERO negative mastery evidence (spaced-review REQ-SR-01 s4 line 22); scheduler still updates; subsequent failures follow normal behavior.
- **Falsifiable check:** After a pattern like miss–pass–miss–pass–miss (5 verdicts, 3 misses non-consecutive), assert skill state is still Fluent AND no struggle-halt trigger (tutor affordance did not surface).

### 3. In-band failures (0.4 ≤ score ≤ 0.7)
- **Pattern:** A Fluent skill receives N gate-tier verdicts with `0.4 ≤ score ≤ 0.7` (firewall in-band range).
- **Behavior:** Mastery state remains Fluent. Each in-band verdict emits a scheduler grade (Again if below passingScore, Good if above) but ZERO mastery evidence (REQ-MM-03 line 44). Stability is affected by the scheduler grade but no demotion occurs. **Struggle-halt counting (gen1, arbitration):** ADR-0021 OWNS struggle-halt semantics and the counter (mastery-model REQ-MM-05 Trigger 2). In-band verdicts produce zero mastery evidence; whether they count toward struggle-halt is governed by ADR-0021, not this ADR. Arbitration ruling (director-gen43, 02:05:00Z): in-band verdicts DO count toward the struggle-halt counter (adaptivity plane distinct from evidence plane).
- **Falsifiable check:** After 10 consecutive in-band verdicts (e.g., normalized score=0.55, passing threshold=0.60), assert skill state is still Fluent AND zero mastery evidence events were recorded for those verdicts. Struggle-halt trigger behavior deferred to ADR-0021.

### 4. Cross-skill failure bursts (different skills, same session)
- **Pattern:** A learner fails multiple Fluent skills in a single session (e.g., clear-misses on 3 different skills within minutes).
- **Behavior:** Each skill's mastery state remains Fluent independently. Per-skill stability resets and per-skill struggle-halt counters advance independently (REQ-MM-05 counting is per-skill, not session-wide). No cross-skill demotion contagion.
- **Falsifiable check:** After 1 clear-miss each on 3 different Fluent skills in one session, assert all 3 skills remain Fluent AND each has an independent stability reset AND no skill demoted another.

### 5. Long-idle return with probe misses (gentle decay path)
- **Pattern:** A Fluent skill idle 45+ days is probed (spaced-review surfaced a review item) and the learner fails the probe (clear-miss).
- **Behavior:** Mastery state transitions to Practiced via the gentle decay path (mastery-model REQ-MM-02 s6 line 39: "worth a refresh" after 45+ idle days plus a missed probe — this is the ONLY decay surface). This is Fluent→Practiced via the gentle path, not a demotion triggered by failure-while-active. The never-demote invariant (s5 line 38) binds active-skill failures; this pattern is the decay path for long-idle skills, governed by REQ-MM-02 s6, not s5. Stability resets. **Ordering vs amnesty (gen1, F2):** The 45-day gentle decay threshold takes precedence over the 21-day amnesty window. A 50-day idle skill that fails on return triggers gentle decay (Practiced state), not amnesty.
- **Falsifiable check:** After a Fluent skill idles 50 days then receives a clear-miss probe, assert skill state becomes Practiced (not Fluent, projection read) AND a subsequent clear-pass can re-promote to Fluent via normal rules.

### 6. Low-confidence clear-passes that later revert to fails
- **Pattern:** A Fluent skill receives a low-vote-agreement clear-pass (score >0.7 but confidence forces in-band treatment per REQ-MM-03 line 53-54), then subsequent clear-misses.
- **Behavior:** The low-confidence pass is treated in-band (zero evidence, or evidence shrunk). The skill remains Fluent if already Fluent (the in-band treatment withheld new evidence but did not revoke prior evidence). Subsequent clear-misses follow pattern 1 or 2 above.
- **Falsifiable check:** Given a Fluent skill, after a low-confidence score=0.75 verdict treated in-band (zero evidence recorded) followed by 2 clear-misses, assert skill state is still Fluent.

## Closed-world rule

**The enumeration above is exhaustive for the REQ-MM-02 s5 never-demote invariant.** Patterns 0–6 cover all combinations given current evidence sources (judge verdicts, deterministic verifiers/quiz keys) and timing axes (consecutive/scattered, active/idle).

The spec obligation is no longer "test one failure sequence and assume all others follow" (an open, unfalsifiable quantifier) but "verify that each enumerated pattern satisfies the never-demote invariant AND the per-pattern behavior."

**Closed-world default (gen1, F4):** An unenumerated failure pattern is bound by the never-demote invariant (mastery-model REQ-MM-02 s5) and MUST NOT change mastery state or trigger struggle responses outside standard item selection (state + retrievability, mastery-model REQ-MM-05). Shipping a failure pattern whose behavior is not covered by this enumeration without an additive ADR extending this enumeration is a spec violation.

**Pattern-outside-the-domain behavior:** If a future phase introduces a new evidence source (e.g., peer review, multi-stage challenges) or a new verdict type (e.g., partial credit), implementers must either: (a) demonstrate it is absorbed by an existing enumerated pattern, OR (b) write an additive ADR extending this enumeration with the new pattern's testable behavior.

## Consistency checks

**Two-key firewall untouched:** This ADR enumerates failure-pattern behaviors WITHIN the firewall's output semantics. The firewall thresholds (0.4 / 0.7), the clear-miss/clear-pass/in-band trichotomy, and the Priya↔Sage sign-off requirement (LANE-DEPENDENCIES) are unchanged. The enumeration translates "any number of subsequent failures" (s5) into testable patterns without altering the firewall contract.

**Gentle decay path preserved:** Pattern 5 (long-idle return with probe miss) is the ONLY decay surface per mastery-model REQ-MM-02 s6 line 39. This is Fluent→Practiced via the gentle path, not a demotion triggered by failure-while-active. The never-demote invariant (s5 line 38) binds active-skill failures; pattern 5 is the decay path for long-idle skills, governed by s6. Verified: REJECTED.md has no prior ruling on decay vs demotion semantics. CONSTRAINTS.md has no constraint on idle-state transitions.

**Struggle-halt disentangled from demotion:** mastery-model REQ-MM-05 s2 line 76 (3 failures trigger struggle-halt into tutor ladder) is a coaching intervention, not a mastery-state change. Pattern 1 clarifies: struggle-halt can trigger while the skill remains Fluent. Pattern 3 defers struggle-halt counting to ADR-0021 (arbitration ruling: in-band verdicts DO count toward the counter — adaptivity plane distinct from evidence plane). No conflict with coach-and-hints REQ-CH-03 (tutor ladder at reflective rung).

**Judge-pipeline dependency verified:** judge-pipeline.md depends-on clause (line 6) names mastery-model as "firewall input — LANE-DEPENDENCIES block 4." The dependency flows one way: judge verdicts → firewall → mastery states. This ADR clarifies the firewall's output semantics for failure patterns; no judge-pipeline behavior changes.

**Constraints/REJECTED check:** No enumerated pattern contradicts CONSTRAINTS.md or REJECTED.md. REJECTED.md line 44 ("Hard-vs-Good is exactly where judge variance lives") confirms the firewall's 0.4–0.7 band captures variance — pattern 3 (in-band failures) is consistent. REJECTED.md line 43 ("EMA continuous mastery score" rejected) confirms discrete state machine — the never-demote invariant enforces this.

## Relaxation path

To admit a new failure pattern (e.g., a new evidence source, a new verdict type, a new decay condition):
1. Write an additive ADR that: (a) names the new pattern (structure, source, trigger), (b) defines its never-demote behavior (or states an exception with rationale if demotion IS allowed), (c) updates this ADR's enumeration section by appending the new entry.
2. Amend judge-pipeline.md and mastery-model.md additively to reference the new ADR.
3. Implement the pattern with tests that falsify the never-demote invariant (or the stated exception).

Migration guidance: if a new evidence source was implemented without defining its failure-pattern behavior, adding it to this enumeration obligates either conformance to an existing pattern or a new ADR entry.
