# ADR-0003: Offline machinery is deferred out of Home Edition v1

**Status:** accepted (genesis, 2026-07-25) · **Item:** ROOT.4.7 · **Trigger:** OPEN-QUESTIONS #5

## Question
Blueprint §2 specifies a full v1 offline story (precached bundle, service worker,
IndexedDB outbox, iOS ITP survival); CONSTRAINTS.md #15 [HARD] frames the product as a
locally-run desktop tool where offline-from-yourself is near impossible.

## Readings
- **A:** offline is Home-Edition v1 scope as written.
- **B:** offline is Hosted-Edition/Phase-5-adjacent; building it for Home contradicts
  the simplicity directive.

## Decision
**Reading B.** ROOT.4.7 (data layer) implements REQ-DL-01 (frozen UX read/write
contract) and REQ-DL-02 (SQLite + in-process reactive cache) only. REQ-DL-03's offline
machinery is deferred alongside the parked Hosted Edition (ADR-0001); the versioned
content bundle (REQ-CP-04) — the precachable asset — is built anyway in Phase 0.

## Reasoning
Least irreversible: deferral is trivially reversible; service-worker/outbox machinery
in a same-machine app is pure added complexity against a [HARD] directive. Adjacent
shards: the iOS/ITP concerns the shard lists only make sense for hosted/LAN use.

## If the other reading is correct
REQ-DL-03 is additive over DL-01/02: the write path already goes through the single
UX contract, so an outbox can be inserted behind it without reworking consumers.
