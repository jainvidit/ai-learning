# ADR-0015 — Event-log serialization: format invariant, and a form-only repair

**Status:** accepted (2026-07-26) · **Scope:** `.program/ledger/events/*.jsonl` and every
role that appends to them · **Pre-repair originals:**
`.program/audits/malformed-events-pre-repair/`

## Context

Validating all 445 event lines during Phase 3 turned up **7 unparseable lines** across two
files. `events/<ID>.jsonl` is the crash-recovery record — the thing a successor generation
reads to reconstruct what happened when a director dies mid-item. One malformed line makes
a line-by-line reader fail on that entire file, so this is a latent recovery failure, not a
cosmetic issue.

The two defects turned out to be **different from each other**, and neither was what the
initial "embedded newlines" reading suggested:

| File | Lines | Defect |
|---|---|---|
| `ROOT.jsonl` | 13, 17, 38, 40 | Records written **TRUNCATED**, missing the closing `}` |
| `ROOT.1.1.4.jsonl` | 6+7 | **Raw CR and LF inside a string value**, splitting one record across two physical lines |

Worth recording: the corrupted `ROOT.1.1.4` record is the implementer's write-up of a
**CRLF-vs-LF determinism defect**, and it was corrupted because its `note` quotes the regex
`/\r?\n/` literally. The same root cause, one layer up. `ROOT.jsonl` additionally carries
mixed line endings (15 of 51 lines CRLF); that was left alone because it does not affect
parsing.

## Decision — the cause is fixed first, then the cleanup

### 1. Event-line format invariant (the actual fix)

Added to every role that appends events — `dream-director.md` (full statement),
`dream-coordinator.md` and `dream-implementer-standard.md` (compact statement), with an
explicit inheritance pointer in the three worktree variants (`-isolated`, `-hardened`,
`-critical`) because they write ledger events to the main checkout by absolute path and
would otherwise be easy to miss. `dream-coordinator-recovery` inherits from
`dream-coordinator` verbatim.

The rule:

- One event = exactly **one line of valid JSON**, terminated by a single `\n`. No pretty-
  printing, no wrapping, no blank lines.
- **Control characters inside string values must be escaped** — `\n`, `\r`, `\t`, `\"`,
  `\\`. A raw newline inside `detail` splits the record and both halves become garbage.
- **Build the line with a serializer, never by hand**, and **verify the file parses
  line-by-line before moving on.** The role files carry the exact command. If the verify
  step does not print `parses`, the writer has corrupted the recovery record and must fix
  it before doing anything else.
- Keep `detail` short. Long narrative goes in a handoff or audit doc referenced by path —
  a `detail` running to hundreds of characters is the condition in which both of these
  defects arose (all four truncated `ROOT.jsonl` records had `detail` strings of 600–1200
  characters).
- Include the `item` key. Coverage is uneven on historical lines, which makes cross-file
  reconstruction harder than it needs to be.

### 2. Auditor check 12 (the standing guard)

`dream-ledger-auditor` gains check 12: every `.jsonl` in `.program/ledger/events/` must
parse line-by-line; **any unparseable line is a BLOCKING finding**, not advisory. The
check names the two known defect classes so a future auditor recognizes them, and is
explicitly told **not to repair** — an auditor that repairs destroys the evidence of how
the ledger broke. `dream-ledger-auditor-deep` inherits it ("all twelve routine checks").

### 3. The repair itself — form only

Repair is legitimate here because **the malformation is a serialization defect, not
evidence of a decision.** No truncated record is ambiguous about what it says; no escaped
character changes what happened. The pre-repair copy preserves the originals regardless, so
nothing is destroyed either way.

Both files were copied **byte-for-byte** to
`.program/audits/malformed-events-pre-repair/` *before* any edit, and the copies were
verified by sha256 and byte count (`ROOT.jsonl` 42897 bytes, sha `6fd44d4a…`;
`ROOT.1.1.4.jsonl` 2492 bytes, sha `7f63fa62…`).

- `ROOT.jsonl`: appended exactly one `}` to each of lines 13, 17, 38, 40. Nothing else on
  any line altered — asserted programmatically that each repaired line equals the original
  plus that single character.
- `ROOT.1.1.4.jsonl`: rejoined the two fragments of the split record and escaped the two
  control characters as `\r` and `\n`. The record is now line 6; the file has 6 records on
  6 lines.

**Nothing else changed: no content, no timestamps, no ordering, no records added or
removed** (beyond the `jsonl_repaired` event appended to each file per the instruction).

Verification after repair:

| Check | Result |
|---|---|
| Record count, `ROOT.jsonl` | 51 before → 51 after |
| Record count, `ROOT.1.1.4.jsonl` | 6 before → 6 after |
| Content, `ROOT.jsonl` | identical under whitespace/brace normalization, all 51 records |
| Content, `ROOT.1.1.4.jsonl` | decoded `note` is 515 chars, **identical character-for-character** to the original raw note text; other 5 records byte-identical |
| Timestamp ordering | preserved (`03:47:35Z … 16:35:00Z`) |
| Whole ledger | **443 lines, 0 malformed** |

A `jsonl_repaired` event was appended to each file recording the line numbers touched, the
defect class, the pre-repair copy path, and that content was preserved.

## Consequence

- The ledger parses end to end. A successor generation can read any event file
  line-by-line without special-casing.
- The originals are recoverable from `.program/audits/malformed-events-pre-repair/`
  indefinitely. If anyone disputes the repair, that directory settles it.
- Format compliance is now checkable rather than hoped for: check 12 runs every audit
  cycle, and the writer-side verify step catches a bad line at the moment it is written
  rather than 40 generations later.

## If wrong

If new malformed lines appear after this, the writer-side verify step is being skipped —
check whether the appending agent used a serializer or hand-assembled the string, which is
visible in its transcript. If a repaired record is ever disputed, diff it against
`.program/audits/malformed-events-pre-repair/`; the comparison must be done on the DECODED
string values, not the raw bytes, since escaping changes the bytes by design.
