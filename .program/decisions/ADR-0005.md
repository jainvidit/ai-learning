# ADR-0005: Beat type vocabulary is the blueprint set; session-end is an authored convention

**Status:** accepted (genesis, 2026-07-25) · **Item:** ROOT.1.2 · **Trigger:** OPEN-QUESTIONS #1

## Question
Blueprint §2/GLOSSARY say beat types are `prose | quiz | playground | terminal |
challenge | widget`; Nova's frozen review says `prose | interactive | exercise | recap`.
Both claim frozen status.

## Readings
- **A:** the blueprint set (shards encode this).
- **B:** Nova's coarser set, with `recap` as a distinct type.

## Decision
**Reading A.** The beat-type Contract (`.program/interfaces/`, from REQ-CP-02) uses the
closed blueprint set. The session-end/recap beat is an **authored convention over a
prose beat** (a frontmatter/anchor marker), not a schema type.

## Reasoning
The blueprint is the synthesis document and the shards — the only spec agents read —
already encode Reading A; REQ-CP-02's scenario 1 names the closed set literally.
Nova's taxonomy reads as a UX abstraction *over* the concrete types (interactive ≈
playground|terminal|widget, exercise ≈ quiz|challenge). Least irreversible: a coarser
rendering-level grouping can be layered on later without a schema change, whereas
splitting a shipped coarse type into concrete ones breaks stable beatIds (REQ-CP-02
scenario 2).

## If the other reading is correct
Add `recap` as a type in an additive schema change and migrate the convention-marked
prose beats; beatId stability for all other beats is preserved.
