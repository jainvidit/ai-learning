# ADR-0022: REQ-CH-01 s1 tutor-invocation context domain enumeration (data-plane isolation contract)

Date: 2026-07-28. Author: implementer-ROOT.7.3.4-gen0.
Status: ratified.
Spec ref: .program/spec/coach-and-hints.md#req-ch-01 scenario 1.

## Context

REQ-CH-01 scenario 1 says "Given **any tutor invocation**, when its assembled context is inspected, then none of: answer keys, verifier source code, exemplar solutions, rubric weights, passingScore, or `improvedPromptExample` are present." The universal quantifier "any tutor invocation" was unfalsifiable over an unenumerated domain (unfalsifiable-criteria survey .program/audits/2026-07-27T0540-unfalsifiable-criteria-survey.md, row coach-and-hints REQ-CH-01 s1). No test suite can cover an open set of invocation contexts, so the criterion could pass review while the guarantee was false for unnamed contexts or rungs.

REQ-CH-01 establishes the data-plane isolation contract: the tutor receives ONLY objectives, instructions, rubric descriptions (no weights), missed-criterion IDs, the current draft, and server-held ladder position. It NEVER receives answer keys, verifier sources, exemplar solutions, unrevealed authored hints, or `improvedPromptExample`. Data-plane isolation is a protected property — it's the architectural guarantee that the tutor "cannot leak what it does not hold" (coach-and-hints.md line 13).

Following ADR-0017/0019/0020/0028 closed-world enumeration precedent: enumerate the invocation contexts bound by REQ-CH-01's data-plane isolation contract, define per-context isolation obligations testably, reject outside the domain (closed-world), relaxation is additive via new ADR.

## Closed-world rule

**The enumeration above is exhaustive for all tutor-invoking surfaces in the ai-learning-app.** Any new exercise type, beat type, or probe mechanism NOT on this list does NOT invoke the tutor until explicitly added by a future additive ADR.

The spec obligation is no longer "test one tutor invocation and assume all others follow" (an open, unfalsifiable quantifier) but "verify that each enumerated context satisfies its isolation obligation AND the post-response leak check."

**Enforcement seam (fail-closed default):** The tutor invocation entry point (model-gateway service tutor-call endpoint) accepts a `contextType` tag enum (values: `playground`, `quiz`, `challenge`, `boss`, `testOut`, `review`). Any `contextType` outside this set is rejected with a typed error (`InvalidContextTypeError` with message "Tutor context type '<type>' is not in the enumerated domain (ADR-0022). To add tutor support for this type, write an additive ADR defining its isolation obligations."). Test assertion form: attempt to invoke the tutor with `contextType: "newExerciseType"` (unenumerated) and assert the call throws `InvalidContextTypeError`.

**Context-outside-the-domain behavior (fail-closed default):** If a future phase introduces a new exercise type or beat type (e.g., peer-review exercises, live collaboration surfaces, SSE-fed real-time pair-programming), that type does NOT invoke the tutor by default. To add tutor support:
1. Write an additive ADR that: (a) names the new context (owning spec/item, location, trigger), (b) defines its data-plane isolation obligation (context IN/OUT, leak check, rung-4 constraints if applicable), (c) updates this ADR's enumeration section by appending the new entry.
2. Amend coach-and-hints.md additively to reference the new ADR.
3. Implement the context with isolation plumbing + leak checks + tests that falsify the obligation.

**Unnamed contexts explicitly excluded (non-invoking):**
- **Terminal beats themselves:** The terminal streams TermEvent sequences (execution-layer.md REQ-EX-02); no tutor invocation on terminal output itself. The paired challenge (context 3) invokes the tutor on the challenge's verification, not on the raw terminal session.
- **Prose beats:** Markdown/island-rendered lesson content (lesson-experience.md REQ-LX-01); no exercise, no tutor.
- **Session-end beats:** Objectives-mapped recap + one retrieval question + curiosity hook (lesson-experience REQ-LX-04 s3). The retrieval question is quiz-like content but the session-end beat compiles to type `prose` (ADR-0005), which has no ExerciseFrame wrapper and no coach button (REQ-LX-01: prose beats are markdown/island-rendered). No tutor invocation (architectural constraint: no coach button exists in prose renderer).
- **Exploration/demonstrate beats:** `attempted`-only completion predicate, zero mastery evidence (lesson-experience REQ-LX-02 s2 firewall). If these beats contain exercises (playground/quiz/challenge), the tutor may be invoked on-demand (button always available per REQ-CH-02 s1) and follows the underlying exercise type's context rules (1/2/3). Zero-evidence status affects mastery accounting (ADR-0021 Trigger 3), NOT tutor-context isolation. Struggle-watcher affordance-surfacing on attempted-only beats is an implementation detail for ROOT.3.1 (may be suppressed to avoid surfacing coach on zero-stakes beats), but on-demand invocations are NOT exempt from isolation obligations.
- **Widget beats:** Custom interactive components (interfaces/beat-model.ts type `widget`). Widgets are read-only demonstrations or simulations with no exercise submission, no gate-tier judgment, no mastery evidence (zero coach surface area). No tutor invocation.

## Per-context falsifiable restatement of REQ-CH-01 s1

For each context in the enumerated domain:

1. **Context assembly:** When a tutor invocation is spawned at any rung (1–4), then the assembled LLM context/prompt contains ONLY: objectives, instructions, rubric descriptions (no weights), missed-criterion IDs from the last gate-tier verdict, the learner's current draft/answer/file-tree, and the server-held rung position.
2. **Forbidden fields absent:** When the assembled context is inspected, then NONE of: answer keys, verifier source code, exemplar solutions, rubric weights, passingScore, `improvedPromptExample`, OR unrevealed authored hints for this item are present in any context field (system prompt, user message, tool definitions, retrieval sources). Check: inspect the assembled context dict for each enumerated context; assert the `authoredHints` field (or equivalent) is absent OR, if present, contains only hints whose rung is at or below the current server-held ladder position (already-revealed hints are not leaks).
3. **Rung-4 method-not-artifact (quiz, playground, and challenge):** When rung 4 output is inspected for a quiz, playground, or challenge, then it walks the full method step-by-step YET does not contain the literal correct option ID (quiz), a verbatim passing prompt (playground), or a complete passing diff/file (challenge). (REQ-CH-03 s2 cross-link.)
4. **Post-response leak check:** When the tutor response is returned, then it passes n-gram duplication checks vs solutions/`improvedPromptExample` and `judgeCriterion` reuse checks (REQ-CH-05 s2). On failure, regenerate once; on second failure, fall back to the authored hint rung. (Implementation: leak-check logic shared across all contexts, injected at the model-gateway tutor-call seam.)
5. **Server-held rung position:** When the ladder position is read, then it came from server state (event log projection or session storage), never from any client-supplied value (REQ-CH-01 s2 cross-link).

These obligations are testable per context: spawn a tutor call at rung 2 and rung 4 for each context, inspect the assembled prompt dict, verify absence of forbidden fields, verify rung-4 output honors method-not-artifact.

## Relaxation path

To admit tutor invocations in a new context (e.g., a new exercise type, a new beat type, a peer-review surface):
1. Write an additive ADR that: (a) names the new context (owning spec/item, location, trigger), (b) defines its data-plane isolation obligation (context IN/OUT, leak check, rung-4 constraints if applicable), (c) updates this ADR's enumeration section by appending the new entry as context 7 (or next number).
2. Amend coach-and-hints.md additively to reference the new ADR.
3. Implement the context with isolation plumbing + leak checks + tests that falsify the obligation.

Migration guidance: if a new exercise type was implemented without defining its tutor context, adding it to this enumeration obligates either conformance to an existing context's rules (if the type is a variant of playground/quiz/challenge) or a new context entry with explicit isolation obligations.

### F8: Additivity honesty and divergence note (MAJOR)

Gen0 Consequences stated "amended additively (domain clause added)" but the shipped coach-and-hints.md s1 reads "Given any tutor invocation IN AN ENUMERATED CONTEXT (ADR-0022: playground/…)" — an in-place narrowing of the pre-existing quantifier "Given any tutor invocation". ADR-0021 recorded an equivalent edit as "REPLACES" (line 86: "domain clause REPLACES the phrase 'any struggling learner'"). Gen0's amendment is a replacement, not pure addition.

**Amendment:** Consequences reworded to match ADR-0021 precedent (line 159: "amended additively" → "amended (domain clause REPLACES the pre-existing quantifier phrase per ADR-0021 additivity precedent)").

**Divergence note (additivity pattern sanctioning):** The sanctioned additive-domain-clause pattern in this program is APPENDING a domain paragraph + trailing sentence to a requirement (as ADR-0020 and ADR-0028 did), NOT editing the pre-existing quantifier in place. Gen0 narrowed s1's quantifier from "Given any tutor invocation" to "Given any tutor invocation in an enumerated context (ADR-0022: …)" following ADR-0021's precedent (which replaced "any struggling learner" with "any learner matching an enumerated struggle trigger"). Both are in-place replacements of universal quantifiers; both are recorded as "REPLACES" in Consequences. The ADR-0021 pattern (replace + record honestly) is the binding pattern here because REQ-CH-01 and REQ-MM-05 both concern universal quantifiers over unbounded domains (any invocation, any learner), and additive domain clauses for universals require narrowing the quantifier. The alternative (restoring pre-existing s1 wording + appending a domain clause) would produce "Given any tutor invocation, when … [domain paragraph appended]", leaving the universal quantifier unfalsifiable again (defeating the ADR's purpose). Recorded as replacement per ADR-0021 precedent.
