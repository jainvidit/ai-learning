# ADR-0026: REQ-DL-03 s3 offline-state domain — enumerate reachable states; network-needed messaging

**Status:** ratified 2026-07-27  
**Item:** ROOT.7.3.8  
**Spec ref:** .program/spec/data-layer-and-offline.md#req-dl-03 scenario 3  
**Trigger:** Unfalsifiable-criteria survey (.program/audits/2026-07-27T0540-unfalsifiable-criteria-survey.md, row data-layer-and-offline REQ-DL-03 s3)

## Context

REQ-DL-03 s3 says "Given **any offline learner** reaching a playground, terminal, or challenge beat, when it renders, then it plainly states that this exercise needs network — it never fakes availability." The universal quantifier "any offline learner" is unfalsifiable over an unenumerated domain: no test suite can cover an open set of offline states (fully synced, partial sync, stale bundle, mid-outbox flush), so the criterion could pass review while the guarantee was false for unnamed states.

This is the same failure mode as CP-05 s1 ("content changes in any way") and API-03 s3 ("any SSE response"), both fixed by enumeration via ADR-0017 and ADR-0019. Following that precedent (enumerate the domain closed-world, per-state testable behaviour, additive relaxation path), this decision enumerates the offline-state domain for REQ-DL-03 s3.

**Critical constraint (ADR-0003 consistency):** ADR-0003 defers REQ-DL-03's offline machinery (service worker, IndexedDB outbox, precached bundle, iOS ITP survival) out of Home Edition v1. Home v1 implements only REQ-DL-01 (frozen UX contract) + REQ-DL-02 (SQLite + reactive cache), NOT REQ-DL-03. Therefore the enumeration below reflects Home v1's **actual reachable states**, not the full theoretical offline domain described in the REQ-DL-03 prose. Any state involving outbox replay, stale precache bundles, or service-worker interception is NOT reachable in Home v1 and is NOT enumerated here.

## The enumerated offline-state domain (Home Edition v1, normative)

REQ-DL-03 s3 applies in exactly **FOUR offline states** reachable in the Home Edition v1:

### State 1: Navigator.onLine = false, without production fakes (browser-detected offline)

- **Detection:** `navigator.onLine === false` in the learner's browser AND the fake AgentRunner/ModelGateway seams (REQ-EX-04 s1 / REQ-MG-03 s1) are NOT the resolved implementation
- **Home v1 reachability:** YES — the browser API reports the offline state even when Home is a locally-run app (e.g., Wi-Fi disconnected, airplane mode, network adapter disabled)
- **Behaviour (REQ-DL-03 s3):** When a playground, terminal, or challenge beat renders while `navigator.onLine === false`, then the exercise frame displays a plain text message stating "This exercise needs network for the model" (or equivalent honest framing), and interactive affordances (Run, Verify, prompt input) are either disabled or show the same message on interaction
- **Testable predicate:** Mock `navigator.onLine = false` in a test, navigate to a lesson containing a playground/terminal/challenge beat, verify the network-needed message appears and submit actions are gated. Executable harness: Playwright E2E tests using `context.setOffline(true)` (@playwright/test ^1.62.0 available, npm run verify:e2e per AGENTS.md). Falsifiability: predicate must FAIL when onLine=true (message absent, Run/Verify enabled).
- **Deferred scope (ADR-0003):** Home v1 does NOT implement precache, so there is no "offline with stale bundle" state; Home v1 does NOT implement an outbox, so there is no "mid-outbox flush" or "offline writes pending" state. The full REQ-DL-03 prose describes those states for the Hosted Edition (parked per ADR-0001) or a future Home Edition phase that reverses ADR-0003's deferral
- **Fakes carve-out:** This state does NOT apply when the fake AgentRunner/ModelGateway (REQ-EX-04 s1 / REQ-MG-03 s1, Phase 0 seams for dev/preview/CI/OFFLINE consumers) is the resolved implementation. With fakes configured, the beat runs normally against cassettes regardless of connectivity (State 4 governs that configuration).

### State 2: Network-reachable but model-gateway HTTP fetch fails (transport error, 5xx, timeout)

- **Detection:** `navigator.onLine === true` but fetch to `/api/playground/run` or `/api/claude-code/exec` fails at the HTTP level (network error, 500/503, timeout) BEFORE the SSE stream opens
- **Home v1 reachability:** YES — the locally-run Home Edition calls the model gateway (Bedrock API), which can fail due to: no internet despite `onLine=true`, firewall/VPN issues, AWS region outages, credential expiry, rate limits, or downed local Next.js server (transport error, not a Next.js error page)
- **Behaviour (REQ-DL-03 s3):** When a playground/terminal/challenge run is submitted and the fetch fails, then the exercise frame shows an error message plainly stating the nature of the failure ("Could not reach the model. Check your network connection." / "Model request timed out." / "Service temporarily unavailable."), and the learner can retry
- **Testable predicate:** Mock fetch to return a network error or 503, submit a playground run, verify the error message appears and retry is offered. Executable harness: Playwright E2E tests mocking fetch failures. Falsifiability: predicate must FAIL when fetch succeeds (error message absent, stream proceeds).
- **Consistency with REQ-DL-03 s3 intent:** The scenario's "never fakes availability" rule means the app must not show a loading spinner indefinitely or pretend the model is running locally; honest failure messaging satisfies the requirement

### State 3: SSE stream opens (200 text/event-stream) then errors or stalls mid-stream (stream-level failure)

- **Detection:** HTTP fetch to `/api/playground/run` or `/api/claude-code/exec` succeeds with 200 text/event-stream, but the stream subsequently: (a) emits an error event, or (b) stalls without a terminal done event AND no heartbeat or data arrives past the REQ-API-03 stated timeout (~20s heartbeat obligation, cite ADR-0019)
- **Home v1 reachability:** YES — per REQ-API-03 + ADR-0019, both endpoints are SSE streams; the HTTP fetch succeeds, then the model call can fail INSIDE the stream due to: Bedrock API errors after connection established, credential expiry mid-call, rate-limit hit during generation, timeout, or heartbeat/data silence past the stated interval
- **Behaviour (REQ-DL-03 s3):** When the stream errors or stalls, then the exercise frame shows an error message plainly stating the nature of the failure ("Stream error: model call failed" / "Stream timeout: no response from model" / error detail from stream event), and the learner can retry. The app must NOT show an indefinite spinner without messaging, which would falsely fake availability.
- **Testable predicate:** Mock SSE stream to open successfully (200) then either emit an error event or stall without heartbeats past the timeout threshold; verify error messaging appears. Executable harness: Playwright E2E tests mocking SSE streams, or integration tests with controlled stream responses. Falsifiability: predicate must FAIL when stream completes normally with terminal done event (error message absent).
- **Detectability basis:** REQ-API-03's ~20s heartbeat obligation (ADR-0019 lines 34, 44) establishes the decidable predicate for stall detection: if no heartbeat or data arrives past that interval, the client can detect the stall and show error messaging rather than an indefinite spinner.

### State 4: Production fakes configured — offline operation with recorded transcripts (fake AgentRunner/ModelGateway)

- **Detection:** The fake AgentRunner/ModelGateway (REQ-EX-04 s1 / REQ-MG-03 s1, Phase 0 seams for dev/preview/CI/OFFLINE consumers) is the resolved implementation, with cassettes/recorded responses configured
- **Home v1 reachability:** YES — REQ-EX-04 s1 states "terminal features run against recorded NDJSON transcripts (cassettes) without a CLI"; REQ-MG-03 s1 describes model-gateway production fakes for "dev/preview/CI/offline consumers." These seams are Phase 0, so they are Home-v1-reachable.
- **Behaviour (REQ-DL-03 s3):** When fakes are configured, playground/terminal/challenge beats run normally against cassettes/recorded responses regardless of connectivity state. State 1's network-needed gating and messaging do NOT apply — the beat behaves as though the model is available, because the fake implementation IS locally available. This is NOT faking unavailable features; the fakes ARE a production surface (REQ-EX-04/MG-03 intent: dev/preview/CI/offline consumers exercise the real UI end-to-end).
- **Testable predicate:** Configure fake runner/gateway, set `navigator.onLine = false`, submit a playground/terminal run, verify it completes successfully using cassette data without showing network-needed messaging. Executable harness: Playwright E2E tests with fakes enabled, or integration tests. Falsifiability: predicate must FAIL when fakes are NOT configured and onLine=false (network-needed message appears, run gated — State 1 behaviour).
- **Consistency with ADR-0003:** Fakes do not require the deferred offline machinery (precache, outbox, service worker). They are a seam for exercising the UI against recorded data, not an offline-sync feature. No expansion of Home v1 offline scope beyond ADR-0003's constraint.

### State 5: LocalDriver spawn fails — claude CLI absent or spawn error (spawn-level failure)

- **Detection:** For terminal beats, LocalDriver attempts to spawn the learner's local claude CLI (REQ-EX-01) but the spawn fails due to: (a) claude CLI not installed (REQ-EX-04 s1's own premise: "environment with no claude CLI installed"), or (b) spawn error (permissions, PATH misconfiguration, binary corruption)
- **Home v1 reachability:** YES — REQ-EX-01 states LocalDriver "spawns the learner's real claude CLI" and "the product states plainly that the agent runs on your machine." REQ-EX-04 s1 explicitly contemplates "environment with no claude CLI installed" as the condition for falling back to fake runner. The spawn-failure predicate is decidable: if spawn throws, State 5 applies; if spawn succeeds, terminal proceeds.
- **Behaviour (REQ-DL-03 s3):** When spawn fails, then the terminal beat shows an error message plainly stating the nature of the failure ("Claude CLI not found. Install it to run terminal exercises." / "Failed to start agent session. Check CLI installation."), and guidance is offered (install link, troubleshooting doc). The app must NOT show an indefinite spinner, which would falsely fake availability.
- **Testable predicate:** Mock LocalDriver spawn to throw an error, navigate to a terminal beat, verify error messaging appears. Executable harness: Integration tests mocking spawn failure, or Playwright E2E tests with CLI uninstalled. Falsifiability: predicate must FAIL when spawn succeeds (error message absent, terminal session starts).
- **HTTP-layer distinction:** Per REQ-EX-01, LocalDriver spawns the CLI locally; the Bedrock dependency lives in the child process. The HTTP hop (`/api/claude-code/exec`) is same-machine and succeeds even if the CLI is absent — the failure is detected AFTER the fetch, when the server attempts to spawn. This is neither State 2 (fetch failure) nor State 3 (stream error); it is a spawn-level failure that requires its own enumeration.
- **Consistency with ADR-0003:** LocalDriver spawn is a Phase 2 (REQ-EX-01) concern, not deferred offline machinery. No precache/outbox/service-worker required. No expansion of Home v1 offline scope.

### What is NOT enumerated and why (ADR-0003 deferred scope)

The following states are described in REQ-DL-03 prose but are **NOT reachable in Home Edition v1** because ADR-0003 defers the machinery that would create them:

- **"Precached bundle, network unavailable":** REQ-DL-03 s1 describes offline prose/quiz lessons rendering from a precached versioned bundle. ADR-0003 defers service-worker precaching out of Home v1, so this state is NOT reachable. Consequence: prose/quiz lessons in Home v1 are fetched on-demand from the Next.js server (running locally), not from a service-worker cache. If `navigator.onLine === false`, the Next.js server may still serve them (same-machine HTTP), so this is effectively State 1 (browser offline) with the caveat that local resources may still work.
  
- **"Stale bundle (outdated precache, fresh bundle available on network)":** REQ-DL-03 s4 describes the precache targeting a versioned static bundle route. No precache in Home v1 → no stale-bundle state.

- **"Mid-outbox flush (offline writes pending, connectivity returns)":** REQ-DL-03 s2 describes quiz attempts queued in an IndexedDB outbox, replayed with idempotency keys when connectivity returns. ADR-0003 defers outbox machinery out of Home v1, so this state is NOT reachable. Consequence: quiz attempts in Home v1 are submitted directly to the server (the locally-run Next.js server writes to SQLite via the data layer). If the network is unavailable, the submit fails (covered by State 2 above), but there is no outbox to queue the attempt.

- **"Partial sync (some content fetched, others missing)":** Not applicable in Home v1 — there is no sync; all content is served from the local Next.js build or fetched on-demand from the local server.

## Closed-world rule

**The enumeration above is exhaustive for Home Edition v1.** Any offline state not on this list is NOT reachable in Home v1 because the machinery to create it (service worker, outbox, precache, sync) was deferred by ADR-0003. If a future phase reverses ADR-0003 and implements REQ-DL-03's full offline machinery, the state enumeration must be amended via the relaxation path below.

REQ-DL-03 s3's falsifiable restatement for Home v1: **In each enumerated state (navigator offline without fakes, HTTP fetch failure, SSE stream failure, fakes configured, spawn failure), when a playground/terminal/challenge beat renders or is interacted with, then honest network-needed or error messaging appears (except State 4 where fakes provide local availability), and the app never fakes unavailable model features with indefinite spinners.**

## Default for unenumerated states (decidability)

Any state not explicitly enumerated above defaults to: **the exercise renders normally and attempts to call the model gateway**. This is the online happy path. If an unenumerated condition causes model-gateway calls to fail, it is caught by State 2 (fetch failure) and handled via error messaging.

Consequence: adding a new detectable offline state (e.g., Bedrock credential expiry detected before fetch) requires amending this ADR to enumerate its behaviour.

## Additive relaxation path (if REQ-DL-03 full scope is implemented)

If a future phase reverses ADR-0003 and implements service-worker precaching + IndexedDB outbox (REQ-DL-03 s1–s2–s4 full machinery), the following states join the enumeration via an additive ADR amendment:

1. **"Precached bundle, network unavailable, prose/quiz lesson":** State 3. Behaviour: lesson renders client-side from precache; quizzes grade locally with outbox queuing. Playground/terminal/challenge beats show network-needed messaging per existing State 1.

2. **"Stale bundle (outdated precache, fresh available)":** State 4. Behaviour: app either (a) shows a dismissible "New content available, refresh to update" banner, or (b) auto-updates the precache in the background and applies on next nav. Decision TBD in the future ADR. Playground/terminal/challenge network-needed messaging unchanged.

3. **"Outbox pending (offline writes queued, connectivity returns)":** State 5. Behaviour: outbox replays queued quiz attempts with idempotency keys; server re-grades authoritatively; UI shows replay progress or silent background flush. Playground/terminal/challenge network-needed messaging transitions to available once connectivity confirmed.

Each new state requires: (a) detection predicate, (b) per-state s3 behaviour for playground/terminal/challenge, (c) testable criterion, (d) Home-v1-reachability ruling (all future states are "NO in v1, YES in v2+").

## Consistency with ADR-0003 (explicit verification per acceptance criterion 3)

**ADR-0003 decision:** REQ-DL-03 offline machinery (service worker, outbox, precache) is deferred out of Home Edition v1. Home v1 implements only REQ-DL-01 (UX contract) + REQ-DL-02 (SQLite + reactive cache).

**This ADR's enumeration is consistent:** Five states are enumerated, and all are reachable in Home v1 WITHOUT the deferred machinery:
- State 1 (`navigator.onLine === false` without fakes) is a browser API, not a precache/outbox state
- State 2 (model-gateway HTTP fetch failure) is a transport-level error case, not an offline-queue state
- State 3 (SSE stream failure mid-stream) is a streaming protocol error case, not deferred machinery
- State 4 (fakes configured) is a Phase 0 production seam (REQ-EX-04/MG-03), not deferred offline machinery
- State 5 (LocalDriver spawn failure) is a Phase 2 execution-layer error case (REQ-EX-01), not deferred machinery

The three deferred states (precached bundle, stale bundle, outbox flush) are explicitly called out in the "What is NOT enumerated and why" section as NOT reachable in Home v1. The enumeration therefore **does not silently expand Home v1 offline scope** — it reflects the constrained scope ADR-0003 established.

**If ADR-0003 is correct:** this enumeration is correct and complete for Home v1.

**If ADR-0003 is later reversed:** the relaxation path above provides the additive amendment procedure to admit the deferred states into the domain without rewriting existing guarantees.

## Per-beat-type messaging obligations (lesson-experience.md cross-reference)

REQ-DL-03 s3 names "playground, terminal, or challenge beat" as the surfaces that must show network-needed messaging. Cross-reference to lesson-experience.md:

- **Playground beat (REQ-LX-06):** ExerciseFrame wrapping the playground editor. Network-needed message appears inside the frame, above or in place of the Run button.
- **Terminal beat (REQ-LX-03, REQ-LX-06):** Persistent SandboxBeat (terminal + paired challenge in one composite frame). Network-needed message appears in the terminal pane, and the prompt input is disabled or shows the message on interaction attempt.
- **Challenge beat (REQ-LX-06):** Paired with terminal in SandboxBeat. Network-needed message appears beside the criteria or in place of the Verify button.

**Prose/quiz beats are explicitly excluded from s3's obligation:** REQ-DL-03 s1 states prose/quiz lessons can render offline (when precache is implemented). In Home v1 (no precache), prose/quiz are served by the local Next.js server, so `navigator.onLine === false` may not prevent their rendering (same-machine HTTP). If the local server is unavailable (e.g., dev server crashed, process killed), fetching prose/quiz content yields a transport error — this is State 2 (HTTP fetch failure), not a distinct failure mode. Next.js error pages (404, 500 from a running server) are NOT offline states; transport errors (cannot connect to server) ARE State 2.

## Test plan (falsifiability per enumerated state)

All tests use **Playwright E2E tests** (`npm run verify:e2e` per AGENTS.md) as the executable harness. `@playwright/test ^1.62.0` is available and provides `context.setOffline(true)` for network mocking. Vitest (`npm test`) runs in node environment without jsdom/happy-dom, so React beat rendering is not executable under unit tests.

### State 1: navigator.onLine = false, without fakes
```typescript
// Playwright E2E test
test('playground shows network-needed message when offline without fakes', async ({ context, page }) => {
  await context.setOffline(true); // Mock navigator.onLine = false
  await page.goto('/lesson/with-playground-beat');
  
  // Assert: network-needed message visible
  await expect(page.getByText(/needs network for the model/i)).toBeVisible();
  // Assert: Run button disabled OR shows message on click
});
```
**Falsifiability:** When `context.setOffline(false)`, the network-needed message must be absent and Run must be enabled. This predicate has both a case that MUST pass (offline → message appears) and a case that MUST fail (online → message absent).

### State 2: model-gateway HTTP fetch failure
```typescript
// Playwright E2E test with fetch mocking
test('playground shows error message on fetch failure', async ({ page }) => {
  await page.route('/api/playground/run', route => route.abort('failed'));
  await page.goto('/lesson/with-playground-beat');
  await page.getByRole('button', { name: /run/i }).click();
  
  // Assert: error message visible
  await expect(page.getByText(/could not reach the model/i)).toBeVisible();
  // Assert: retry affordance present
});
```
**Falsifiability:** When fetch succeeds (route NOT mocked to abort), the error message must be absent and the stream must proceed normally. This predicate has both success and failure cases.

### State 3: SSE stream opens then errors/stalls mid-stream
```typescript
// Playwright E2E test with SSE stream mocking
test('playground shows stream error on mid-stream failure', async ({ page }) => {
  await page.route('/api/playground/run', route => {
    route.fulfill({
      status: 200,
      contentType: 'text/event-stream',
      body: 'event: error\ndata: {"error":"Stream failure"}\n\n'
    });
  });
  await page.goto('/lesson/with-playground-beat');
  await page.getByRole('button', { name: /run/i }).click();
  
  // Assert: error message visible
  await expect(page.getByText(/stream error|stream failure/i)).toBeVisible();
});
```
**Falsifiability:** When stream completes normally with terminal done event, the error message must be absent. This predicate has both error and success cases.

### State 4: Fakes configured
```typescript
// Playwright E2E test with fakes enabled
test('playground runs successfully offline when fakes configured', async ({ context, page }) => {
  // Configure fake runner/gateway via environment or test setup
  await context.setOffline(true); // Mock navigator.onLine = false
  await page.goto('/lesson/with-playground-beat');
  await page.getByRole('button', { name: /run/i }).click();
  
  // Assert: run completes using cassette data, NO network-needed message
  await expect(page.getByText(/needs network/i)).not.toBeVisible();
  await expect(page.getByText(/completed/i)).toBeVisible(); // or equivalent success indicator
});
```
**Falsifiability:** When fakes are NOT configured and offline, State 1 behaviour must apply (network-needed message appears, run gated). This predicate distinguishes fake-configured from non-fake-configured offline states.

### State 5: LocalDriver spawn fails
```typescript
// Playwright E2E test or integration test with spawn mocking
test('terminal shows CLI-absent error when spawn fails', async ({ page }) => {
  // Mock LocalDriver to throw spawn error (integration test setup or E2E with CLI uninstalled)
  await page.goto('/lesson/with-terminal-beat');
  
  // Assert: error message visible
  await expect(page.getByText(/claude cli not found|failed to start agent/i)).toBeVisible();
  // Assert: guidance offered (install link, etc.)
});
```
**Falsifiability:** When spawn succeeds, the error message must be absent and the terminal session must start. This predicate has both spawn-failure and spawn-success cases.

**Summary of falsifiability:** Each test has a predicate with BOTH a case that must pass (condition present → expected behaviour) AND a case that must fail (condition absent → expected behaviour absent). This establishes decidability and avoids vacuous "presence-or-absence" criteria where a test could pass by always returning one answer.
