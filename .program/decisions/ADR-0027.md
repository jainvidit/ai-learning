# ADR-0027 — REQ-WA-01 s4 learner-facing Workshop UI surface domain enumeration

Date: 2026-07-28. Author: implementer-ROOT.7.3.9-gen0.
Status: ratified.
Spec ref: .program/spec/workshop-and-artifacts.md#req-wa-01 scenario 4.

## Context

The unfalsifiable-criteria survey (.program/audits/2026-07-27T0540-unfalsifiable-criteria-survey.md) classified REQ-WA-01 scenario 4 as a clear match — a universal quantifier "all learner-facing Workshop UI" over an unenumerated domain. The scenario states:

> Given all learner-facing Workshop UI, when audited, then no git terminology or raw git operations are exposed.

This is unfalsifiable over an open set of unnamed/future surfaces: no test suite can cover "all UI" when the domain is not defined. The criterion could pass review while the guarantee was false for unnamed surfaces. Following the ADR-0017 precedent (CP-05 s1 "content changes in any way" fixed by enumeration), this decision enumerates the Workshop-touching learner-facing UI surfaces closed-world.

## Enumerated learner-facing Workshop UI surfaces (normative)

REQ-WA-01 s4 applies to exactly **SEVEN** learner-facing Workshop UI surfaces:

### 1. Workshop exercise beats within lessons
- **Location**: Lesson pages (module 5–14) containing Workshop-flagged exercises; rendered as SandboxBeat (lesson-experience REQ-LX-06) with persistent terminal (terminal-experience REQ-TX-01, REQ-TX-03)
- **Owning specs**: lesson-experience.md (beat rendering), workshop-and-artifacts.md REQ-WA-01, curriculum-content.md REQ-CC-05 (content declares workshop flag)
- **Git-exposure obligation**: No git terminology in exercise prose, no checkpoint/restore controls at the beat level (restore UX is surface #3), no git branch/commit/tag UI, no diff views, no raw `.git` paths
- **Current state**: MODIFIED (Terminal.tsx ownership moves to PersistentTerminalHost; SandboxBeat composite frame is new)

### 2. Workshop dock tab in bottom dock
- **Location**: Bottom dock (terminal-experience REQ-TX-02), Workshop-specific tab alongside per-sandbox session tabs
- **Owning specs**: terminal-experience.md REQ-TX-02, workshop-and-artifacts.md REQ-WA-01 (declared as dependency in frontmatter)
- **Git-exposure obligation**: Tab label is "Workshop" (or artifact-related name like "My Tools"), never "Git" / "Repo" / "Branch"; pulsing indicator reflects session activity (agent running in Workshop dir), never raw git state (commit count, dirty status, branch name); tab controls (close/detach/focus) are session controls, not git operations
- **Current state**: NEW UI (dock itself is new per terminal-experience, Workshop tab is Phase 4 addition)

### 3. Artifact shelf page
- **Location**: Dedicated route (e.g., `/artifacts` or `/shelf`) showing the accumulated artifact collection
- **Owning specs**: workshop-and-artifacts.md REQ-WA-04
- **Git-exposure obligation**: Each artifact shows title, plain-language "what this does for you" benefit, and live health badge (healthy/regressed/missing from ArtifactHealth projection); no commit hashes, no tag names (`good/<exerciseId>` tags are server-side metadata), no branch UI, no git log view; restore/repair actions use plain-language labels (surface #5)
- **Current state**: NEW UI

### 4. Artifact shelf teaser on dashboard hero
- **Location**: Dashboard hero (dashboard-and-wayfinding REQ-DW-01), condensed view of artifact shelf
- **Owning specs**: dashboard-and-wayfinding.md REQ-DW-01, workshop-and-artifacts.md REQ-WA-04 (declared as dependency in dashboard frontmatter)
- **Git-exposure obligation**: Same as surface #3 (shelf page), condensed: artifact count/highlights, health badges, CTA to full shelf — no git state visible
- **Current state**: NEW UI (dashboard hero is REPLACED per dashboard-and-wayfinding)

### 5. Regression repair session UI
- **Location**: Scoped repair session triggered by regression banner (surface #6), renders as a focused sandbox/terminal environment for debugging one artifact
- **Owning specs**: workshop-and-artifacts.md REQ-WA-05 (regression repair)
- **Git-exposure obligation**: Banner copy uses normalizing developer framing ("your Module 9 hook stopped firing — this happens to every developer; want to investigate?"), never git blame language ("your commit broke this"); repair session shows the affected artifact's verifier output and sandbox environment, never git diff UI; success/failure surfaces as "fixed" / "still broken", not commit/revert operations; the "patch-in loaner" offer (after two failed repairs) is labeled as "use a reference version" or "skip for now with a working baseline", never "cherry-pick" / "git apply patch"
- **Current state**: NEW UI

### 6. Regression banner (non-blocking in-lesson or on arrival)
- **Location**: In-lesson banner when cumulative re-verification detects a regression (REQ-WA-05 s2), or on lesson entry if precondition check fails (REQ-WA-05 s4)
- **Owning specs**: workshop-and-artifacts.md REQ-WA-05
- **Git-exposure obligation**: Banner text uses plain-language artifact health state ("your Module 9 hook isn't firing" / "this lesson needs a working CLAUDE.md file"), never git state language ("your working directory is dirty" / "HEAD is detached"); CTA is "investigate" / "fix now" / "repair", never "revert" / "reset" / "checkout"; dismissible without requiring action (non-blocking per s2)
- **Current state**: NEW UI

### 7. Artifact-created celebration animation
- **Location**: Triggered by server-confirmed `artifact_created` / `artifact_verified` events (frontend-platform REQ-FP-04 s2, celebration-trigger domain ADR-0023 row 6)
- **Owning specs**: frontend-platform.md REQ-FP-04, workshop-and-artifacts.md REQ-WA-04 ("triggers a shelf animation via the celebration ladder")
- **Git-exposure obligation**: Animation and accompanying text celebrate the artifact's capability ("You built a custom CLAUDE.md!" / "Your first skill is live!"), never git-specific language ("Tagged good/claude-md!" / "Committed to workshop repo!"); no commit hashes or git operation names in celebration copy
- **Current state**: NEW (celebration API and motion stack are new per frontend-platform REQ-FP-04)

## Surfaces explicitly EXCLUDED and why

### Server-side git plumbing (never surfaces to learner)
- Workshop git operations (auto-checkpoint, tag on pass, restore-forward checkout-into-new-commit) are server-side plumbing per REQ-WA-01; the learner never sees git commands, commit messages, or the `.git` directory
- Nightly git-bundle backup (REQ-WA-01 s5) runs server-side with no learner-visible UI

### Exercise precondition failure UI (not a distinct surface)
- REQ-WA-05 s4: "Given an exercise requiring `artifact:claude-md:healthy` while that artifact is regressed, when the learner reaches it, then the precondition surfaces (repair path offered)"
- This is a specialization of surface #6 (regression banner on lesson entry), not a separate UI surface — covered by that enumeration

### Generic lesson/dashboard navigation (not Workshop-specific)
- Lesson resume chip (lesson-experience REQ-LX-07), rail jump-nav (REQ-LX-04), breadcrumbs (dashboard-and-wayfinding REQ-DW-03) apply uniformly to all lessons, including Workshop-flagged ones, but do not expose Workshop-specific state
- Obligation: these surfaces must not leak git state for any lesson, but this is a general lesson-experience requirement, not a Workshop-specific one under REQ-WA-01 s4

### Sidebar Workshop entry (not distinct from dock tab surface #2)
- Dashboard-and-wayfinding REQ-DW-03 mentions "Workshop entry (live-session pulse)" in the sidebar
- This is a navigation link to the Workshop view (full shelf page surface #3) or dock focus (surface #2); it shares the surface #2 git-exposure obligations (no git terminology, pulse indicates session activity)

## Closed-world rule

**The enumeration above is exhaustive.** REQ-WA-01 s4's obligation ("no git terminology or raw git operations") applies to these seven surfaces and no others until explicitly added via the relaxation path below. Creating a new learner-facing Workshop UI surface without amending this ADR first is a spec violation.

The spec obligation is no longer "audit all UI and assume no git leaks" (an open audit) but "verify that each surface on the normative list satisfies the s4 git-abstraction obligation per its per-surface testable criteria."

## Per-surface falsifiable restatement of REQ-WA-01 s4

For each surface in the enumerated domain, the git-abstraction obligation is testable as follows:

1. **Text audit**: Grep all UI copy (component strings, i18n keys, prose content) for git-specific terms: `git`, `commit`, `branch`, `tag`, `HEAD`, `checkout`, `reset`, `revert`, `diff`, `log`, `cherry-pick`, `rebase`, `merge`, `clone`, `push`, `pull`, `fetch`, `stash`, `.git`. **Hits allowed only in**:
   - Server-side plumbing code (never rendered to learner)
   - Developer docs/comments (not user-facing strings)
   - Generic words with non-git primary meanings in context (e.g., "tag" in "price tag", "commit" in "commit to learning")

2. **Control audit**: Enumerate all interactive controls (buttons, links, dropdowns, modals) on each surface. Each control's label, tooltip, and triggered action must use plain-language artifact/session/debugging framing, never git operation names. **Example violations**:
   - "Revert to last good commit" → FAIL (git operation name)
   - "Restore working version" → PASS (plain language, git plumbing hidden)
   - "Show diff" → FAIL (git-specific; use "Compare changes" if needed, though diff UI is not specced)
   - "Investigate" / "Repair" → PASS (debugging framing)

3. **State display audit**: Enumerate all state indicators (badges, banners, status labels) on each surface. Each must display artifact-level or session-level state (healthy/regressed/missing, agent running/idle/complete), never git repository state (branch name, dirty/clean, commit count, detached HEAD). **Example violations**:
   - "Branch: main" → FAIL
   - "2 uncommitted files" → FAIL
   - "Module 9 hook regressed" → PASS (artifact health state)
   - "Agent running in Workshop" → PASS (session state)

4. **Path display audit**: If any surface shows file paths (e.g., in repair session output), the `.git` directory and its contents must never appear in learner-visible path lists, file pickers, or terminal output that the UI actively renders. (The terminal may stream raw `ls -la` output containing `.git` if the learner explicitly requests it — that is scoped command output, not UI chrome.)

5. **Celebration/notification copy audit**: All workshop-related celebration text (surface #7), success toasts, completion messages must celebrate artifact creation/verification, never git operations. **Example violations**:
   - "Committed your first artifact!" → FAIL
   - "Tagged good/claude-md" → FAIL
   - "You built your first Claude config!" → PASS

## Relaxation path

To admit a new learner-facing Workshop UI surface:
1. Write an additive ADR that: (a) names the new surface (location, owning spec, purpose), (b) states its git-exposure obligation using the five-audit template above, (c) updates this ADR's enumeration section by appending the new entry.
2. Amend workshop-and-artifacts.md additively to reference the new ADR.
3. Implement the surface with s4 plumbing (plain-language abstractions, no git terminology) or document an exception with rationale.

## Notes

- ROOT.5.1's nightly-backup flag (listed in DECISIONS-PENDING.md per task brief) is out of scope for this ADR — nightly git-bundle backup (REQ-WA-01 s5) is server-side plumbing with no learner-visible UI, thus not a "learner-facing Workshop UI surface" under s4's domain.
- The "no hard reset anywhere in the UI" clause in REQ-WA-01 s1 is a control-audit obligation (surface #3 shelf restore controls and surface #5 repair session must not offer hard-reset actions) but is not the same as the s4 git-terminology obligation — both apply, independently verifiable.
- Repair session (surface #5) and regression banner (surface #6) are distinct surfaces: the banner is a non-blocking notification/CTA, the session is a focused debugging environment. The banner may appear without the session being open (learner dismisses it); the session exists only when the learner clicks "investigate".
