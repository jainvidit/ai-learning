# ADR-0008: npm workspaces, not pnpm, for the package split

**Status:** accepted (2026-07-25) · **Item:** ROOT.1.10 · **Trigger:** sizing finding #11

## Question
ROOT.1.5 originally listed `pnpm-workspace.yaml`, but the repo uses npm
(`package-lock.json`, no `packageManager` field) and every AGENTS.md verification
command is npm-based.

## Decision
npm workspaces. The split (ADR-0002: packages only, one Next app) is expressed in
`package.json` `workspaces`; no new package manager is introduced.

## Reasoning
Least irreversible and least contract-changing: a pnpm migration would invalidate the
one named command set (AGENTS.md) that every leaf's point-5 verification depends on,
and would touch owner-visible tooling for zero spec requirement. No shard names a
package manager.

## If wrong
A later pnpm migration is mechanical (`pnpm import` reads package-lock.json); the
package boundaries — the actual deliverable — carry over unchanged.
