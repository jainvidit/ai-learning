# ADR-0018 — Per-shard enumeration ADRs scheduled as ledger items (Decision level)

Date: 2026-07-27. Author: director-gen42, on owner directive (gen42 launch message).
Status: ratified.

## Context

The unfalsifiable-criteria survey (.program/audits/2026-07-27T0540-unfalsifiable-
criteria-survey.md) found 8 clear universally-quantified criteria over unenumerated
domains in Phase 1–4 shards, plus 3 borderline. CP-05 already demonstrated the failure
mode: a universal criterion passed review while false, and was fixed only by enumeration
(ADR-0017 + Amendment 1) after two burned implementation generations. The survey's
disposition ("enumerate per-shard immediately before the owning phase decomposes") was a
recommendation with no enforcement — a future generation could decompose a phase whose
shards were still open-world.

## Decision

1. **One ledger item per affected shard — 11 items, ROOT.7.3.1–ROOT.7.3.11** — under a
   new container ROOT.7.3 (child of ROOT.7, ordering-exempt per ADR-0007). Each item's
   exit is a ratified enumeration ADR + (where needed) an additive shard amendment,
   following the ADR-0017 pattern: enumerate the domain closed-world, reject outside it,
   relaxation is additive via new ADR.
2. **Each item blocks its owning capability's readiness** via `depends_on` on the
   capability that carries the affected REQ — so the coordinator that would decompose it
   cannot be dispatched until the shard is falsifiable. This is deliberately an edge on
   the capability, not on the phase: phase gates stay pure MS-02 checkpoints.
3. **Placement under ROOT.7, not under each phase**: ordering exemption lets any
   enumeration item be worked early in spare capacity, instead of serializing every
   phase boundary behind an ADR-writing step. The `depends_on` edge, not the parent,
   carries the constraint.
4. **New glossary level `Decision`** (leaf): exit is a ratified ADR + evidence of
   consistency with adjacent shards; point 5 of the leaf test (named verification
   command) does not apply — same exemption class as Probe and Gate (ADR-0007).
5. **ADR numbers pre-reserved** so file_ownership globs are disjoint and the overlap
   scan stays clean: ADR-0019…ADR-0029, one per item, mapping recorded in each item file.

## Notes and readings considered

- **Survey discrepancy noted, directive followed:** the survey states "All Phase 1–4;
  none Phase-0-blocking", yet api-and-streaming REQ-API-03 is owned by ROOT.1.3 in
  Phase 0, and MS-03's first consumer is the Phase 0 Gate. The edges above bind ROOT.1.3
  and ROOT.1.8 accordingly; ROOT.7.3.1 and ROOT.7.3.10 are therefore near-term and
  should be dispatched before ROOT.1.1.4 closes the 1.1 subtree.
- **Rejected: encoding as phase-level depends_on** — would stall entire phases on
  paperwork and mix decision-work into gate semantics.
- **Rejected: writing the 11 ADRs immediately** — owner directive is explicit ("do not
  write them now"); also enumeration benefits from the knowledge of the phases that
  precede each shard's consumption.
- **ROOT.7.3.11 owns only its ADR file** (no shard glob): ROOT.1.1.4 is in flight
  against content-pipeline.md; if ratification finds a gap requiring a shard edit, the
  item is re-scoped after 1.1.4 closes.

## Reversal path

Each edge is removable by ADR if an enumeration proves unnecessary; each enumeration is
relaxable additively per the ADR-0017 pattern. Deleting an unstarted ROOT.7.3.x item
cancels cleanly (status cancelled, edge removed).
