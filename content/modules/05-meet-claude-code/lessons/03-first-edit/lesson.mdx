## Level up: changing things

Last lesson you made Claude read files for you — completely safe, since looking can't break anything. Now you'll CHANGE something.

The exercise below uses the same sandbox style: a tiny project (this time a "team snack menu") that you've never seen. Still unbreakable — fresh copies on demand.

## Anatomy of a good edit request

Your prompting skills from modules 02 and 04 matter even more when directing edits. A good request names:

- **WHAT** should be different (not HOW to code it — you don't need to know that)
- **WHERE**, if you know it (which file, which line, which section)
- What **DONE** looks like (what should the file say after the change?)

Example: "In the menu, change the Friday snack from donuts to fruit, and update the note at the top to say the menu was revised."

You described OUTCOMES. Claude figures out the code changes.

## The Edit tool

When you ask for an edit, you'll see Claude announce it: "Editing menu.md…" It reads the file FIRST (the loop again: gather context, then act), proposes the change, and makes it.

## The most important habit: verify

After ANY edit, ask Claude to show you the changed part. Or ask: "Read the file back — does it now say X?"

Never assume. Observe. This is the trust-but-verify habit from module 03, applied to actions instead of answers.

<Callout kind="tip">
Request, then verify. This habit — checking that what you asked for actually happened — is 80% of working well with agents. Every time.
</Callout>
